# 開発ガイドライン

## 1. ブランチ命名規則
Gitのブランチ名は、作業内容や目的がひと目でわかるように「プレフィックス（接頭辞） ＋ ケバブケース（ハイフン区切り）」で統一する。

| プレフィックス | 用途 | ブランチ名の例 |
| :--- | :--- | :--- |
| **`docs/`** | ドキュメント（設計書、ガイドライン、README等）の作成・修正 | `docs/screen-designs`, `docs/db-schema` |
| **`feature/`** | 新機能の追加、画面の実装、インフラの構築など | `feature/cart-function`, `feature/ecs-setup` |
| **`fix/`** | バグや不具合の修正 | `fix/s3-upload-error`, `fix/login-bug` |
| **`refactor/`** | 動作を変えずにコードの構造や設計を改善・整理する時 | `refactor/api-response-format` |

### 命名のルール
* すべて**小文字の半角英数字**を使用する。
* 単語の区切りは、スペースやアンダースコア（`_`）ではなく、**ハイフン（`-`）**を使用する。
* 作業対象の画面や機能が明確な場合は、画面ID（`scu-01`など）を含めると追跡しやすくなる。
