# SCA-04: 注文履歴一覧画面

## 1. 基本情報

- **物理名:** `admin-order-list`
- **対象:** 管理者権限確認済みの管理者。
- **利用環境:** PCブラウザ前提。スマートフォン専用レイアウトは対象外。
- **目的:** 全ユーザーの成立済み注文（成立後のキャンセル済みを含む）を検索・一覧確認し、SCA-05へ遷移する。
- **遷移先:** SCA-05（注文詳細）、SCA-01（管理者ログイン）、SCA-07（権限不足）。
- **共通画面:** CMN-03、CMN-04。
- **対象外:** 一覧からの状態変更・一括キャンセル、CSV出力、未成立注文・カート・入力途中データの表示、並び替え操作。
- **記載範囲:** 表示・検索・追加取得・復帰・状態別文言・API連携。注文成立判定、状態遷移、モック決済・返金の内部処理は要件定義・機能設計で定義する。
- **文言:** 要件定義にも同じ文言を記載し、API設計時に表示条件・結果コードとの対応を確認する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 共通枠・検索エリア

- CMN-03の「注文管理」を現在位置として示し、本文末尾に静的フッターCMN-04を配置する。
- タイトル「注文履歴一覧」、通知領域、キーワード欄、注文状況選択欄、「検索」「条件をクリア」を配置する。

| 項目 | 仕様 |
| --- | --- |
| 対象 | 全ユーザーの成立済み注文。成立後のキャンセル済みも含む。 |
| キーワード | 前後空白除去後100文字以内。超過時はAO01を表示し送信しない。 |
| 検索対象・一致条件 | 注文番号、注文時点の注文者氏名・注文者メールアドレス・受取人氏名のいずれかに部分一致。現在の会員情報・保存済み配送先は検索に使用しない。 |
| 注文状況 | 「すべて」を初期値とする単一選択。SCA-05・ユーザー側と共通の状態定義のうち、今回実装する状態だけを選択肢にする。 |
| 条件の組み合わせ | キーワードの4項目間はOR、キーワード条件と注文状況はAND。空欄キーワードはキーワード条件なし、「すべて」は状態条件なし。 |
| 実行 | 検索ボタンまたは検索欄のEnter。日本語変換確定中は実行しない。状態選択変更だけでは送信しない。 |
| クリア | キーワード空欄・注文状況「すべて」に戻し、条件なしで先頭から検索する。 |
| 範囲・件数 | 読み込み済み分に限定せず対象全注文を検索。初回・検索・追加取得とも最大50件。 |
| 順序 | 注文確定日時降順、同一日時は注文ID降順。 |
| 追加取得 | 実行済み条件と直前の成功応答の継続情報を使用。入力欄の未確定編集は使用しない。 |

- 注文状況の不正値はAO14を表示し送信しない。
- 状態選択肢の定数管理／API取得はAPI設計で確定する。API取得方式で失敗した場合はAO15と「選択肢を再取得」を表示し、選択欄・検索・クリア・追加取得を非活性にする。条件を勝手に「すべて」に変更しない。既存の一覧があれば保持し、詳細遷移は可能とする。初回は選択肢取得成功後に一覧を取得する。
- 個人情報を含み得る検索キーワードはURLやブラウザの永続ストレージに保存せず、画面復元に必要なメモリ内で保持する。再読み込みで保持できない場合は条件なしとする。

### 2.2 注文一覧

- PC向けテーブル形式。必要に応じ表領域を横スクロール可能にし、列や操作を重ねない。
- 次のデータがある場合だけ「もっと見る」を表示する。スクロールによる自動取得は行わない。
- 全件取得済みかつ表示1件以上ならAO06。0件表示は取得成功によって判定する。

| 項目 | 表示・動作 |
| --- | --- |
| 注文ID | 詳細遷移、重複排除、行更新に保持する。注文番号と同一かはAPI設計で確定する。 |
| 注文番号 | 利用者向け注文番号を表示。欠損時は「取得できません」。 |
| 注文確定日時 | JSTの「YYYY/MM/DD HH:mm」。 |
| 注文者氏名 | 注文時点の氏名。先頭30文字、超過時は「…」。 |
| 注文者メールアドレス | 注文時点のメールアドレスを全文表示。必要に応じ折り返す。 |
| 受取人氏名 | 注文時点の受取人氏名。先頭30文字、超過時は「…」。全文は詳細で確認できる。 |
| 代表商品・点数 | 注文時の明細番号順で先頭となる明細の商品名を先頭25文字まで表示。超過時は「…」。注文時の全明細数量合計を「合計N点」と表示する。 |
| 合計請求金額（税込） | 注文確定時の税込総額を円単位・小数なし・3桁区切り（例：￥6,440（税込））。キャンセル・モック返金後も確定時の総額を表示する。 |
| 注文状況 | 現在の状態を共通対応表の表示名で表示。未定義・欠損時はAO08とし、行自体は除外しない。 |
| モック決済・返金状態 | 決済状態と取消／返金状態をそれぞれ判定・表示。返金不要と確認できる場合は「対象外」。欠損・未定義の場合は当該状態にAO09を表示し、正常な状態表示は残す。 |
| 詳細 | 注文IDを指定してSCA-05へ遷移。ID欠損時は非活性としAO11を表示する。 |

- 省略記号は文字数に含めない。氏名等の全文は詳細で確認する。
- 文字列はテキスト表示としHTMLを実行しない。色だけで状態を区別しない。
- 金額・日時・点数・氏名等の欠損や不正は「取得できません」、商品情報欠損は「商品情報を取得できません」。0円・0点・現在日時で補完しない。
- 金額・数量合計はAPI値を整形して表示し、画面で再計算しない。

### 2.3 操作性

- 入力・選択・検索・クリア・詳細・追加取得・復旧操作をキーボードで操作できること。
- 詳細リンクには注文番号を含む識別可能な名前を付ける。番号欠損時も識別できる注文ID等を用いる。
- 追加取得でページ先頭へ移動しない。ボタン消滅時も一覧末尾等にフォーカス先を確保する。
- ローディング・エラー・追加取得完了を支援技術でも認識できるようにする。

## 3. アクセス・操作制御

### 3.1 認証・権限

- 初回・復帰時はCMN-03と確認処理を共有し、認証・権限確認前にはフォーム・注文データを表示しない。
- 未ログイン・認証無効確定時は表示・復元データを破棄し、SCA-04を戻り先としてSCA-01へ遷移。期限切れと判別できる場合のみAL08を引き継ぐ。
- 認証有効・権限不足時は表示・復元データを破棄しSCA-07へ遷移する。
- 確認通信失敗はAO02と「再読み込み」。CMN-03のAH04と二重表示しない。
- ログアウト・管理者切替時も注文データ・検索条件・復元データを破棄し、別セッションに復元しない。

### 3.2 操作可否

認証・権限確認済みを前提とする。

| 状態 | 検索・クリア・追加取得 | 詳細遷移 | CMN-03の通常遷移・ログアウト |
| --- | --- | --- | --- |
| 通常 | 可 | 可 | 可 |
| 初回・検索・先頭再取得中 | 非活性 | 一覧非表示 | 可 |
| 追加取得中 | 非活性 | 可 | 可 |
| 復元後の対象行再取得中・失敗 | 可 | 可。対象行に最新情報未確認である旨を表示 | 可 |

- 本画面の読み取り通信を理由としてCMN-03の通常遷移・ログアウトを抑止しない。
- 未送信の検索入力を理由にAH05・AH06の離脱確認を表示しない。

## 4. アクション・イベント

### 4.1 初回・再読み込み・タブ復帰

1. 認証・権限を確認する。
2. 初回は条件なし。それ以外はメモリ内で保持できる実行済み条件で先頭から最大50件を取得する。保持できなければ条件なし。
3. 成功時は一覧を表示。条件なしで0件はAO03、条件ありで0件はAO05。継続情報に応じ「もっと見る」またはAO06を表示する。
4. 取得失敗時はAO04と「再読み込み」。0件とみなさない。

- SCA-05からの復帰時は4.4を優先し、同一の復帰に対して先頭取得と対象行取得を重複実行しない。
- 初回以外で未確定の検索入力があっても取得には実行済み条件を使う。入力中の条件と表示中の結果条件を混同させない。

### 4.2 検索・クリア

1. キーワードをトリムし、100文字制限と選択値を検証。AO01・AO14の場合は通信しない。
2. 条件を確定し、既存一覧・継続情報・追加取得エラーをリセットする。
3. 一覧を非表示にして先頭取得。成功時は結果に置き換え、0件も条件有無で区別する。
4. 検索失敗時はAO07と「再試行」。再試行は失敗した実行済み条件を使用する。
5. クリアはキーワード空欄・状態「すべて」で同じ先頭取得を行う。

### 4.3 もっと見る

1. 次の履歴があり取得中でない場合のみ、実行済み条件・前回成功時の継続情報で取得する。
2. 既存一覧を残し、ボタンを非活性にして「読み込み中…」。
3. 成功時は末尾に追加。同一IDは重複表示せず、取得内容を既存行へ反映する。既知の最新情報を古い値で上書きしない制御は共通の応答管理に従う。
4. 継続情報は成功時のみ進める。次がなければボタンを隠し、表示1件以上ならAO06。
5. 通信失敗は既存一覧を残しAO10と「再試行」。取得位置を進めない。
6. 続きから取得不可の場合はAO12と「先頭から再読み込み」。実行済み条件は維持する。

### 4.4 詳細遷移・復帰

- 詳細遷移前に、同一管理者のメモリ内に実行済み条件・取得済み一覧・継続情報・スクロール位置を保持する。
- 対象注文IDでSCA-05へ遷移する。

| SCA-05からの復帰状態 | 制御 |
| --- | --- |
| 更新・キャンセルの成功確定 | 実行済み条件で先頭から再取得し、現在の状態・絞り込み結果を反映する。 |
| 変更なし | 認証確認後、可能な範囲で一覧・位置を復元し、閲覧した注文の最新情報を取得する。条件不適合・対象参照不可・復元不可なら実行済み条件で先頭再取得する。 |
| 更新・キャンセルの結果不明 | 変更なしとして扱わない。SCA-05側の結果確認を優先する。再訪問等で本画面が表示された場合は未解決操作を消さず、実行済み条件で先頭再取得し、対象操作の確認はSCA-05へ引き継ぐ。一覧取得だけで操作成功・失敗を断定しない。 |
| 復帰情報を保持できない | 条件なしで先頭から取得する。 |

- 対象行の最新取得だけ失敗した場合は既存行を残し、当該行に「最新情報未確認」、AO13と「再試行」を表示する。再試行は対象行の最新情報を取得する。先頭からの「再読み込み」も利用可能とする。
- 復元した他の行は前回取得時点の情報であり、全件の最新性を保証しない。
- 画面離脱・検索変更・管理者切替・先頭再取得前の古い応答で現在の表示を上書きしない。
- いずれの取得でも認証無効・権限不足は3.1の制御を優先する。

## 5. 状態・メッセージ一覧

| ID | 状態 | 文言・操作 |
| --- | --- | --- |
| AO01 | キーワード超過 | 検索キーワードは100文字以内で入力してください。 |

| AO06 | 全件表示完了・1件以上 | すべての注文履歴を表示しました。 |
| AO07 | 検索失敗 | 注文の検索に失敗しました。再試行してください。／再試行 |
| AO08 | 注文状況不明 | 状況を確認できません |
| AO09 | 決済・返金状態不明 | 決済・返金状態を確認できません |
| AO10 | 追加取得失敗 | 続きの注文履歴を取得できませんでした。再試行してください。／再試行 |
| AO11 | 注文ID欠損・参照不可 | この注文の情報を表示できません。注文一覧を再読み込みしてください。／再読み込み |
| AO12 | 継続取得不可 | 続きの注文履歴を取得できません。先頭から再読み込みしてください。／先頭から再読み込み |
| AO13 | 復帰時の対象行再取得失敗 | 最新の注文情報を取得できませんでした。表示内容が最新でない可能性があります。再試行してください。／再試行 |

- 操作ラベル：検索、条件をクリア、詳細、もっと見る、再読み込み、再試行、先頭から再読み込み、選択肢を再取得。
- 処理中：読み込み中…。補助表示：取得できません、商品情報を取得できません、対象外、最新情報未確認。
- 期限切れ案内はSCA-01のAL08を使用する。取得失敗は再試行成功等で解消されるまで当該領域に残す。
