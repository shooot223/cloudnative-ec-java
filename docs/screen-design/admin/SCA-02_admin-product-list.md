# SCA-02: 商品管理一覧画面

## 1. 基本情報

- **物理名:** `admin-product-list`
- **対象:** 管理者権限確認済みの管理者。
- **利用環境:** PCブラウザ前提。スマートフォン専用レイアウトは対象外。
- **目的:** 未削除商品の検索・一覧確認、新規登録・編集への遷移、削除を行う。
- **遷移先:** SCA-03（商品登録・編集）、SCA-01（管理者ログイン）、SCA-07（権限不足）。
- **共通画面:** CMN-03、CMN-04。
- **対象外:** 一覧上の価格・在庫・公開状態等の直接編集、CSV入出力、削除済み商品の表示・復元、並び替え操作。
- **記載範囲:** 表示・検索・取得・削除確認・結果照会・遷移・文言・API連携。論理削除、注文記録保持、在庫・注文との整合性、画像保管、操作記録の内部方式は要件定義・機能設計で定義する。
- **文言:** 要件定義にも同じ文言を記載し、API設計時に表示条件との対応を確認する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 共通枠・通知・検索

- CMN-03の「商品管理」を現在の機能カテゴリとして表示する。本文末尾に静的フッターCMN-04を配置する。
- タイトルは「商品管理一覧」。タイトル付近に「商品を新規登録」ボタンを1か所配置する。
- タイトルの下に完了・失敗・結果不明の通知領域を設ける。
- 検索キーワード欄、「検索」「条件をクリア」を配置する。公開状態等の追加絞り込み欄は今回設けない。

| 項目 | 仕様 |
| --- | --- |
| 取得対象 | 公開・非公開、販売可能・販売停止、在庫0を含む未削除の全商品。 |
| キーワード対象 | 商品名・商品概要のいずれかへの部分一致。詳細説明・商品IDは対象外。 |
| 入力 | 前後空白除去後50文字以内。超過時はAP01で送信しない。 |
| 実行 | 検索ボタンまたは検索欄のEnter。日本語変換確定中は実行しない。 |
| 空欄・クリア | 条件なしで先頭から取得する。クリア時は入力欄も空にする。 |
| 検索範囲 | 読み込み済み分だけでなく、取得対象の全商品。 |
| 取得件数・順序 | 初回・検索・追加取得とも最大50件。商品ID降順。 |
| 追加取得 | 実行済み検索条件と前回成功時の継続情報を使用する。未確定の入力は使用しない。 |

### 2.2 商品一覧

- PC向けテーブル形式。必要に応じて表領域を横スクロール可能にし、列・操作を重ねない。モバイルカードへの切り替えは行わない。
- 次のデータがある場合だけ「もっと見る」を表示する。自動スクロール取得は行わない。
- 全件取得済みかつ表示1件以上ならAP06。0件表示は対象検索結果の取得成功によって判定する。

| 項目 | 表示・動作 |
| --- | --- |
| 商品ID | 表示し、編集・削除の対象指定に使用する。 |
| サムネイル | 現在の画像URL。比率を保持し、商品名等の代替テキストを付ける。未設定・失敗時はNo Image。代替切り替えを繰り返さない。 |
| 商品名 | 先頭30文字、超過時は「…」。省略記号は文字数に含めない。削除確認では全文を表示する。 |
| 税抜価格・税込価格 | 税抜を主表示、税込を補助表示。例「￥1,800（税抜）／￥1,980（税込）」。API値を円単位・小数なし・3桁区切りに整形し、画面で税計算しない。 |
| 在庫数 | 「N点」。0は「0点（売り切れ）」と表示する。 |
| 公開状態 | 公開・非公開フラグに従い「公開」「非公開」。一覧では参照のみ、変更はSCA-03で行う。 |
| 販売設定 | 「販売可能」「販売停止」。在庫・公開状態とは独立した設定として表示する。 |
| 最終更新日時 | JSTの「YYYY/MM/DD HH:mm」。登録日時に置き換えない。 |
| 編集 | 商品IDを指定してSCA-03編集モードへ遷移する。 |
| 削除 | 対象商品を示す削除確認を開く。 |

- 非公開・販売停止・在庫0はいずれも新たな購入ができない。販売設定が「販売可能」だけで購入可能と表現しない。
- 文字列はテキスト表示とし、HTMLを実行しない。価格・在庫・日時・状態の欠損や不正は「取得できません」。0円・在庫0・公開等に補完しない。
- 商品IDまたは削除に必要な版情報を取得できない場合は削除不可とし、再取得を案内する。商品ID不明の場合は編集も不可。

### 2.3 削除確認・操作性

- 対象の商品IDと省略しない商品名、AP07を表示する。商品名欠損時は「商品情報を取得できません」とIDを表示する。
- 「キャンセル」「削除する」を配置し、初期フォーカスはキャンセル。ダイアログ内にフォーカスを保ち、Escで取消可能とする。
- 取消時は元の削除ボタンへ戻す。削除開始時はダイアログを閉じ、対象行で処理中表示する。
- 削除・再取得後は一覧見出し等へフォーカスを移す。通信結果・エラーは支援技術でも認識可能とする。
- 検索・新規登録・編集・削除・追加取得・復旧をキーボードで操作できること。行の編集・削除には商品ID・商品名を含む識別可能な名前を付ける。

## 3. アクセス・操作制御

### 3.1 認証

- 初回・復帰時はCMN-03と認証・権限確認を共有する。確認中は検索フォーム・管理データを表示しない。
- 未ログイン・認証無効確定時は表示を破棄し、戻り先SCA-02としてSCA-01へ遷移する。期限切れと判別できる場合だけAL08を引き継ぐ。
- 認証有効・権限不足は表示を破棄してSCA-07へ遷移する。
- 確認通信失敗はAP02と再読み込み。CMN-03のAH04と重複表示しない。
- 削除結果照会中の認証無効・権限不足も同じ扱いとする。未解決操作は保持し、再認証・再権限確認後に結果照会を再開する。

### 3.2 操作可否

認証・権限確認済みを前提とする。

| 状態 | 検索・追加取得 | 新規登録・編集 | 削除 | CMN-03の通常遷移・ログアウト |
| --- | --- | --- | --- | --- |
| 通常 | 可 | 可 | 可 | 可 |
| 初回・検索・先頭再取得中 | 非活性 | 新規登録は可、一覧内操作は非表示 | 非表示 | 可 |
| 追加取得中 | 非活性 | 可 | 非活性 | 可 |
| 削除確認ダイアログ | 背景操作不可 | 背景操作不可 | ダイアログのみ可 | 背景操作不可 |
| 削除通信・結果照会中 | 非活性 | 非活性 | 非活性 | 非活性 |
| 削除処理中・結果不明の再確認待ち | 非活性 | 非活性 | 結果確認だけ可 | 非活性 |

- CMN-04に操作要素はなく、遷移抑止状態を連携しない。
- 検索文字の未送信編集だけを理由に離脱確認は出さない。
- 結果不明のまま画面再読み込み・ブラウザ終了が起きても、未解決操作を失わず復帰後の確認を優先する。

## 4. アクション・イベント

### 4.1 初回・再読み込み・タブ復帰

1. 認証・権限を確認する。
2. 未解決の削除操作があれば4.6の結果照会を優先し、新規削除を開始しない。
3. 初回は条件なし、再読み込み・復帰時は保持できる実行済み検索条件で先頭から最大50件取得する。条件を保持できない場合は条件なしとする。
4. 成功時は一覧、条件なし0件はAP03、条件あり0件はAP05を表示する。
5. 初回取得失敗はAP04と再読み込み。認証・権限エラーは3.1に従う。
6. SCA-03からの完了通知は一覧取得の成否と独立して表示し、再読み込みで繰り返さない。

### 4.2 検索・クリア

1. 入力を検証し、超過ならAP01とする。
2. 実行済み条件を更新して一覧・継続情報・追加取得エラーをリセットする。
3. 一覧を非表示にして読み込み中表示。先頭から取得し、新しい結果に置き換える。
4. 検索失敗はAP12と再試行。再試行は失敗した実行済み条件を使用する。
5. クリアも条件なし検索として同じ処理を行う。

### 4.3 もっと見る

1. 続きがあり、取得中・削除未解決でない場合のみ追加取得する。
2. 既存一覧を残し、「もっと見る」を「読み込み中…」へ変更する。
3. 成功時は末尾へ追加する。同一商品IDは重複表示せず、版情報等で新しいと判断できる場合のみ既存行を更新する。単に後着した応答を最新とは扱わない。
4. 継続情報は成功時だけ進める。失敗はAP13と同じ取得位置への再試行。
5. 継続情報失効時はAP14と先頭から再読み込み。実行済み検索条件は保持する。

### 4.4 登録・編集からの復帰

- 新規登録はSCA-03新規モード、編集は商品ID付き編集モードへ遷移する。
- 新規登録成功後は検索条件なしで先頭から取得し、AP18を表示する。
- 編集保存成功後は実行済み検索条件で先頭から取得し、AP19を表示する。検索条件に合わなくなった商品を残さない。
- キャンセルで戻る場合は同一管理者の検索条件・取得済み一覧・位置を可能な範囲で復元する。復元できなければ保持条件で先頭から取得する。
- 復元時も認証確認を行う。最新情報を照合して条件適合性を確認できない場合は、先頭から再取得する。
- 保存後の一覧取得だけ失敗した場合は、保存完了通知を維持してAP20と一覧の再読み込みを表示する。保存を再送しない。

### 4.5 削除実行

1. AP07で対象を確認する。送信前に操作識別情報を確保し、商品ID・確認時の版情報とともに削除APIへ送信する。
2. 対象行を「削除中…」にし、3.2に従って操作を抑止する。
3. 成功時は対象行を除去してAP08を表示する。削除結果を確定させてから通常の遷移抑止を解除し、実行済み検索条件で先頭から一覧を再取得する。
4. 再取得に成功した場合のみ、現在の検索結果に応じて空状態・追加取得・全件表示を決定する。表示行が消えただけでAP03・AP05としない。
5. 一覧再取得だけ失敗した場合はAP15と再読み込みを表示する。削除は再送しない。
6. 対象が既に削除済み・不存在と確定した場合はAP09とし、同様に先頭から再取得する。自分の削除成功とは断定しない。
7. 版の競合はAP16。対象の最新情報を再取得し、一覧を更新する。削除の自動再送はせず、利用者が最新内容で再度確認した場合だけ新しい削除操作を開始する。最新情報を取得できなければ再取得を案内し、その対象の削除を止める。
8. 失敗確定時はAP10、利用者向けの削除不可理由があれば併記して通常操作へ戻す。通信切断・タイムアウト・結果が確定しないサーバーエラーは失敗確定に分類しない。
9. 結果不明はAP11とし、4.6の照会へ進む。

### 4.6 削除結果照会・再開

- 削除APIを自動再送せず、元の操作識別情報で結果を照会する。初回照会後も未解決なら「削除結果を確認」を表示する。

| 確認結果 | 表示・操作 |
| --- | --- |
| 当該削除の成功確定 | AP08。先頭から一覧再取得。 |
| 対象削除済み・不存在を確定、当該操作の成功とは特定できない | AP09。対象を表示対象外として一覧再取得。 |
| 未実行・失敗確定かつ再操作可能 | AP10。最新情報を取得し、通常操作を再開。再削除は改めて確認する。 |
| 処理中 | AP17と結果確認。通常操作の抑止を維持。 |
| 結果不明・照会失敗 | AP11と結果確認。通常操作の抑止を維持。 |

- 一覧にないことだけで削除成功、商品が存在することだけで削除失敗と判定しない。
- 「操作が見つからない」だけでは未実行確定としない。バックエンドの確定結果・再操作可否に従う。
- 再読み込み・再訪問・再ログイン後も同じ操作の照会を再開する。権限がなければ結果を表示しない。
- 画面離脱・検索変更・認証切替・再取得前の古い応答で一覧や操作状態を上書きしない。

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 管理者用セッション情報 | 結果の参照権限確認。 |
| 送信 | 元の削除操作識別情報・必要に応じ商品ID | 対象操作の特定。 |
| 受信 | 操作識別情報・商品ID・当該操作の状態 | 成功、未実行・失敗確定、処理中、不明の分岐。 |
| 受信 | 対象商品の削除済み・不存在の確定情報 | 当該操作成功との区別、一覧除外の可否。 |
| 受信 | 再操作可否・失敗理由・照会結果・エラー種別 | 通常操作再開または確認継続。 |
| 再開時に取得・復元 | 未解決の操作識別情報と対象商品 | 再読み込み・再ログイン後の照会再開。 |

- 操作識別情報の確保・保持・有効期間と、未発見時の安全性判定は機能設計で定義する。単なる一覧再取得で結果照会を代替しない。

### 6.5 競合時の最新商品情報（SCA-03と共用可）

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 管理者用セッション情報・商品ID | 最新商品参照。 |
| 受信 | 商品の最新表示項目・版情報・対象の有無・処理結果 | 内容更新、再確認、既削除・不存在の処理。 |

### 6.6 画面間の連携（API通信なし）

| 情報 | 用途 |
| --- | --- |
| 新規／編集モード・対象商品ID | SCA-03への遷移。 |
| 実行済み検索条件・一覧復元情報・スクロール位置 | SCA-03からの復帰。 |
| 保存結果・対象商品ID・一度だけ表示する完了通知 | 登録・編集後の再取得と通知。 |
| 削除処理中・結果不明・通常遷移許可 | CMN-03と操作抑止を共有。CMN-04への連携は不要。 |
