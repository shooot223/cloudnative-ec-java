# SCA-05: 注文詳細画面

## 1. 基本情報

- **物理名:** `admin-order-detail`
- **対象:** 管理者権限確認済みの管理者。
- **利用環境:** PCブラウザ前提。スマートフォン専用レイアウトは対象外。
- **目的:** 特定の成立済み注文（成立後のキャンセル済みを含む）について、注文時点の商品明細・金額内訳・配送先・注文者情報・モック決済／返金状態を確認し、注文状況の更新および注文のキャンセル操作を行う。
- **遷移先:** SCA-04（注文履歴一覧）、SCA-03（商品登録・編集）、SCA-01（管理者ログイン）、SCA-07（権限不足）。
- **共通画面:** CMN-03、CMN-04。
- **対象外:** 注文明細の数量変更・商品追加・部分キャンセル・一部返金、配送先や注文者情報の書き換え、キャンセル済み注文の復活、管理者の内部メモの登録。
- **記載範囲:** 画面構成、表示項目、注文状況更新・注文キャンセル操作、未保存変更の離脱確認、競合・結果照会、SCA-04への復帰連携、文言、API連携項目。注文状態の遷移可能ルール、キャンセル時の在庫戻し、モック返金・取消の内部処理は要件定義・機能設計で定義する。
- **文言:** 要件定義にも同じ文言を記載し、API設計時に表示条件・結果コードとの対応を確認する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 共通枠・導線・通知エリア

- CMN-03の「注文管理」を現在位置として示し、本文末尾に静的フッターCMN-04を配置する。
- タイトル「注文詳細（管理）」と、上部に「注文履歴一覧へ戻る（SCA-04）」ボタン／リンクを配置する。
- タイトルの下に、状態更新完了、キャンセル完了、更新・キャンセル失敗、競合、結果不明等の全体通知領域を設ける。
- 注文詳細取得後はAD01（テスト注文の記録である旨）を表示し、キャンセル済み注文の場合はAD02も表示する。

### 2.2 注文基本情報・ステータス操作エリア

- 見出し「注文基本情報・状態管理」を表示する。

| 項目 | 表示・動作仕様 |
| --- | --- |
| 注文ID | 対象指定・結果照会に使用する識別情報として保持する（注文番号と別管理の場合は管理用IDとしても参照表示可）。 |
| 注文番号 | 利用者向け注文番号を表示する。欠損時は「取得できません」。 |
| 注文確定日時 | JSTの「YYYY/MM/DD HH:mm」で表示する。 |
| 最終更新日時 | 注文データの最終更新日時をJSTの「YYYY/MM/DD HH:mm」で表示する。 |
| 現在の注文状況 | 現在の注文状況を共通対応表の表示名で表示する。色だけで区別しない。未定義・欠損時はAD08。 |
| 注文状況の変更選択欄 | 現在の注文状況から通常の状態変更が可能な場合、変更先の注文状況を選択する欄を表示する。変更不可の状態（キャンセル済み・完了確定状態等）では非活性または非表示とする。キャンセルは専用操作のみとし、通常状態の選択肢には含めない。 |
| 注文状況を更新する | 選択欄で現在の保存済み状態と異なる有効な変更先が選択されている場合に活性とし、押下時に状態更新処理を開始する。 |
| 選択を戻す | 注文状況の選択を変更中の場合に表示し、現在の保存済み状態へ戻す。 |
| 注文をキャンセルする | 当該注文がキャンセル可能な状態である場合に表示し、押下時にキャンセル確認ダイアログ（2.6）を開く。既にキャンセル済みまたはキャンセル不可の状態では非活性としてAPIの利用者向け不可理由を表示とする。 |
| キャンセル日時・理由（キャンセル済み時） | キャンセル済みの場合のみ、キャンセル日時（JST）と登録された利用者向けキャンセル理由を表示する。理由未登録が確認できた場合は「理由の登録はありません」、欠損・不正時は「取得できません」。 |

- 状態表示・操作は以下で統一する。最終的な操作可否は最新API応答に従う。

| 現在の状態 | 通常の変更先 | キャンセル |
| --- | --- | --- |
| 注文受付 | 管理者操作なし。システム処理完了後に手配中へ更新 | 可 |
| 手配中 | 発送済み（模擬発送） | 可 |
| 発送済み | なし | 不可 |
| キャンセル | なし | 不可 |

- 発送済みからの差し戻し・キャンセル済みからの復活は行わない。

### 2.3 注文商品明細エリア

- 見出し「注文商品明細」を表示し、注文明細番号の昇順でテーブル表示する。
- 商品名・単価・数量・小計はすべて**注文確定時点の記録**を表示する。現在の商品マスタの値で置き換えない。
- 見出し付近にAD11を表示し、サムネイル画像が現在の登録画像であり注文時点と異なる可能性がある旨を案内する。

| 項目 | 表示・動作仕様 |
| --- | --- |
| 注文明細ID・明細番号 | 行識別・順序表示に使用する。 |
| 商品ID | 表示し、現在の商品が存在（未削除）する場合はSCA-03（商品編集画面）へのリンク（または参照導線）とする。削除済み・不存在の場合はリンクを設けず「（削除済み商品）」等を添える。 |
| サムネイル画像 | 現在登録されている参照可能な画像URLを表示する。未設定・商品削除・取得失敗時はNo Imageとし、切り替えを繰り返さない。 |
| 注文時商品名 | 注文時点の商品名を省略せず全文テキスト表示する。欠損時は「商品情報を取得できません」。 |
| 注文時税込単価 | 注文時点の税込単価を「￥1,980（税込）」の形式で表示する（注文時点の税抜単価も保持している場合は併記可）。 |
| 数量 | 注文時点の数量「N点」を表示する。 |
| 注文時税込明細小計 | 注文時点の税込小計を表示する。画面で単価×数量を再計算しない。 |

- 成立済み注文で明細が0件・取得不正の場合はAD10と「再読み込み」を表示し、正常な0件注文として扱わない。

### 2.4 金額内訳・モック決済／返金情報エリア

- 見出し「金額内訳・決済／返金情報」を表示する。

| 項目 | 表示・動作仕様 |
| --- | --- |
| 商品合計（N点） | 注文時点の明細数量合計。 |
| 税込商品合計 | 注文確定時の税込商品合計。 |
| 送料（税込） | 注文確定時の税込送料。 |
| 決済手数料 | 注文確定時の税込手数料（「￥0」も省略せず表示）。 |
| 合計請求金額（税込） | 注文確定時の税込総額。キャンセル・モック返金後も確定時の総額を保持して表示する。 |
| 支払い方法・テストカード | 注文時点の支払い方法表示名、使用した架空テストカードの表示名・模擬下4桁を表示する。 |
| モック決済状態 | 現在のモック決済状態を共通対応表の表示名で表示する。未定義・欠損時はAD12。 |
| モック返金・取消状態 | キャンセル等に伴うモック返金・取消処理の状態（「対象外」を含む）を表示する。未定義・欠損時はAD12。 |
| モック返金・取消額 | APIが返す対象額を注文総額とは別欄に表示する。画面で総額をコピーして補完しない。 |

### 2.5 配送先・注文者情報エリア

- 見出し「配送先・注文者情報」を表示する。すべて**注文時点の記録**を参照専用で全文表示し、現在の会員マスタや保存配送先で補完しない。

| 項目 | 表示仕様 |
| --- | --- |
| 受取人氏名 | 注文時点の受取人氏名（省略せず全文表示）。 |
| 郵便番号 | 注文時点の7桁を「〒123-4567」に整形。欠損・不正時は「取得できません」。 |
| 住所 | 注文時点の都道府県・市区町村・番地・建物名・部屋番号。建物名等が未入力と確認できる場合はその部分を省略する。 |
| 電話番号 | 注文時点の電話番号（先頭の0を保持）。 |
| 注文者氏名・会員ID（任意） | 注文時点の注文者氏名（および管理参照用の会員識別情報）。 |
| 注文者メールアドレス | 注文時点の注文者メールアドレス（全文表示）。 |

### 2.6 注文キャンセル確認ダイアログ

- 「注文をキャンセルする」押下時にダイアログを開き、注文番号、注文者氏名、合計請求金額、および確認文言（AD13）を表示する。
- 利用者向けキャンセル理由の入力欄（任意入力、前後空白除去後200文字以内）を配置し、SCU-09（ユーザー側注文詳細）で注文者に表示される旨を明記する（内部メモは入力させない）。
- キャンセル実行後は元に戻せないこと、および必要な在庫戻し・モック決済取消／返金記録が行われることを案内する。
- 「閉じる（やめる）」と「キャンセルを実行する」を配置し、初期フォーカスは「閉じる」に置く。Escキーでも閉じ、元のボタンへフォーカスを戻す。

### 2.7 操作性

- 状態選択、更新、選択を戻す、キャンセルダイアログ操作、一覧へ戻る、商品リンク、再読み込み・結果確認をすべてキーボードで操作できるようにする。
- 商品名・氏名・住所・キャンセル理由等はすべてテキストとして表示し、HTMLを実行しない。

## 3. アクセス・入力・操作制御

### 3.1 認証・対象注文制御

- 初回・復帰時はCMN-03と認証・権限確認を共有し、確認中は注文データや個人情報・操作欄を表示しない。
- 未ログイン・認証無効確定時は表示と未保存選択を破棄し、対象注文IDを含むSCA-05を戻り先としてSCA-01へ遷移する（期限切れはAL08）。
- 認証有効・権限不足時は表示を破棄してSCA-07へ遷移する。
- 注文IDが未指定・形式不正、または対象注文が存在しない・未成立の場合は注文詳細を表示せず、SCA-05内にAD04と「注文履歴一覧へ戻る（SCA-04）」を表示する（SCA-06へは遷移しない）。

### 3.2 入力・選択条件

| 項目 | 条件 | エラー文言ID |
| --- | --- | --- |
| 変更後の注文状況 | 必須（状態更新時）。現在の注文状況から遷移可能な有効な注文状況コードであること。 | AD14 |
| キャンセル理由（キャンセル実行時） | 任意。前後空白除去後に200文字以内。未入力時は未設定として送信し、「理由未登録」という文言自体は保存しない。 | AD15 |

- 不正な選択や文字数超過がある場合は更新・キャンセルAPIを呼び出さない。
- 注文状況またはキャンセル可否・版情報・基本情報が欠損・未確認の場合は、状態更新およびキャンセル操作を非活性にし、再取得を促す。

### 3.3 処理中の操作可否と未保存変更の確認

| 状態 | 状態選択・更新 | 注文キャンセル | 一覧へ戻る・商品リンク | CMN-03の通常遷移・ログアウト |
| --- | --- | --- | --- | --- |
| 通常（変更なし） | 許可状態なら可 | 許可状態なら可 | 確認なしで可 | 確認なしで可 |
| 注文状況を選択変更中（未保存） | 更新・戻す可 | 非活性（選択を戻すと可） | AH05で確認後に可 | AH05／AH06で確認後に可 |
| キャンセル確認ダイアログ表示中 | 背景操作不可 | ダイアログ内のみ可 | 背景操作不可 | 背景操作不可 |
| 状態更新・キャンセル通信中・結果照会中 | 非活性 | 非活性 | 非活性 | 非活性（遷移抑止） |
| 更新・キャンセル結果不明（再確認待ち） | 非活性 | 非活性 | 結果確認のみ可。通常遷移は抑止 | 非活性（遷移抑止） |

- 注文状況の選択欄が現在の保存済み状態から変更されている場合（またはキャンセルダイアログで理由を入力中の場合）を「未保存変更あり」とし、一覧へ戻る・商品リンク・CMN-03ナビゲーション・ログアウト時に破棄確認（AH05・AH06）を行う。

## 4. アクション・イベント

### 4.1 初期表示・再読み込み

1. 管理者認証・権限と対象注文IDを確認し、3.1に従う。確認通信失敗時はAD03と「再読み込み」を表示する。
2. 未解決の状態更新・キャンセル操作がある場合は、4.4の結果照会を優先する。
3. 管理用注文詳細取得APIを呼び出し、初回はローディング表示を出す。
4. **取得成功時:**
   - 注文基本情報、商品明細、金額内訳・モック決済／返金情報、配送先・注文者情報を表示し、版情報と遷移可能な注文状況選択肢を反映する。
   - AD01を表示し、キャンセル済みならAD02も表示する。
   - 操作識別情報を準備する。
5. **取得失敗時:**
   - 対象なし・未成立・ID不正はAD04とSCA-04への導線を表示する。
   - 初回取得の通信失敗はAD05と「再読み込み」「注文履歴一覧へ戻る」を表示する。
   - 既に表示がある状態での再取得失敗は既存表示を残し、AD09と「再読み込み」を表示して状態更新・キャンセル操作を止める。

### 4.2 注文状況を更新する

1. 選択された注文状況が現在の保存済み状態と異なり、遷移可能な有効値であることを検証する（不正時はAD14）。
2. 選択欄・更新ボタン・キャンセルボタン・戻る導線・CMN-03の通常遷移を非活性にし、「更新中…」と表示する。
3. 操作識別情報、注文ID、確認時の版情報、変更後の注文状況コードを注文状況更新APIへ送信する。
4. **成功時:**
   - APIから返却された最新の注文詳細（現在の注文状況、最終更新日時、版情報、次回遷移可能な選択肢等）で画面を更新し、未保存状態を解除する。
   - AD16（「注文状況を更新しました。」）を表示し、SCA-04への復帰用状態として「更新成功確定」を記録する。
5. **更新競合・遷移不可判明時:**
   - 他の操作等で版情報や注文状況が既に変化していた場合はAD17を表示し、変更選択を保持して更新操作を止め、「最新の注文情報を読み込む」を案内する。AD26で未保存選択の破棄確認後に取得し、取得成功時だけ置き換える。取得失敗時はAD09と入力を保持する。自動再送しない。
6. **失敗確定時:**
   - AD18を表示し、選択状態を保持したまま再操作可能にする。
7. **結果不明時（タイムアウト・通信切断等）:**
   - 自動再送せず、AD19を表示して4.4の結果照会へ進む。

### 4.3 注文をキャンセルする（「注文をキャンセルする」→「キャンセルを実行する」）

1. キャンセル確認ダイアログ（AD13）を開き、キャンセル理由の前後空白除去後の文字数（200文字以内）を検証する（超過時はAD15）。
2. 「キャンセルを実行する」押下時、ダイアログおよび画面の操作・CMN-03の通常遷移を非活性にし、「キャンセル処理中…」と表示する。
3. 操作識別情報、注文ID、確認時の版情報、利用者向けキャンセル理由を注文キャンセルAPIへ送信する。
4. **成功時:**
   - ダイアログを閉じ、最新の注文詳細（注文状況＝キャンセル、キャンセル日時・理由、モック決済の取消／返金状態・対象額、最終更新日時、版情報）で画面を更新する。
   - AD20（「注文をキャンセルしました。」）およびAD02を表示し、SCA-04への復帰用状態として「キャンセル成功確定」を記録する。
   - キャンセルに必要な在庫処理・モック取消／返金記録は一体で確定した結果として表示する。個別の返金再試行操作は設けない。
5. **競合・既にキャンセル済み・キャンセル不可状態への変化時:**
   - 元の操作の成功が確認できた場合はAD20を表示する。別操作によるキャンセル等と確認できた場合は最新詳細を反映してAD22を表示する。現在の状態だけで元の操作成功と断定しない。
   - 発送済み等へ変化しておりキャンセル不可となった場合や版競合の場合はAD17を表示し、再実行を止める。入力した理由は保持し、最新詳細の取得後に改めてキャンセル確認を行う。取得失敗時はAD09とし更新操作を止める。
6. **失敗確定時:**
   - 注文キャンセルが未成立と確定した場合はAD23を表示し、入力したキャンセル理由を保持したまま再試行または閉じる操作を可能にする。
7. **結果不明時（タイムアウト・通信切断等）:**
   - 自動再送せず、AD19を表示して4.4の結果照会へ進む。

- 「閉じる」・Escでダイアログを閉じると未送信の理由を破棄する。通信中・結果確認中は閉じる操作も抑止する。フォーカスをダイアログ内に保ち、終了後は元の操作または見出しへ移動する。

### 4.4 更新・キャンセル結果照会・再開

- 状態更新またはキャンセルAPIの応答が確認できない場合は、元の操作識別情報で結果を照会する。未解決の間は「処理結果を確認」を表示し、重複操作を抑止する。

| 確認結果 | 表示・操作 |
| --- | --- |
| 当該更新・キャンセルの成功確定 | 最新注文詳細を画面に反映し、AD16またはAD20を表示する。SCA-04への復帰状態を「更新・キャンセル成功確定」とし、通常遷移抑止を解除する。 |
| 未実行・失敗確定かつ再操作可能 | 最新注文詳細を同期し、AD18またはAD23を表示して通常操作を再開する。 |
| 処理中・結果不明・照会失敗 | AD19またはAD24と「処理結果を確認」を維持する。SCA-04への復帰状態は「結果不明」として保持し、変更なしとして扱わない。 |

- 再読み込み・再訪問・再ログイン後も、未解決の操作識別情報があれば結果照会を再開する。

- 操作記録が見つからないことだけで未実行とみなさず、再操作可否を確認する。
- 成功確定後の最新詳細取得に失敗した場合は、成功通知とAD25を表示する。成功した要求は再送せず、詳細再取得が成功するまで更新・キャンセル操作を止める。通常の一覧復帰は可能とし、成功確定を引き継ぐ。
- 再ログイン後は結果照会を再開するが、破棄済みの選択・理由入力の復元は保証しない。
- 通常遷移の抑止中も、認証無効・権限喪失時の必要な遷移は妨げない。

### 4.5 注文履歴一覧へ戻る・商品編集への遷移・タブ復帰

- 「注文履歴一覧へ戻る」押下時、未保存の選択変更があればAH05で確認し、同意後にSCA-04へ遷移する。
- SCA-04へ戻る際は、SCA-04の4.4に従い「更新・キャンセル成功確定」「変更なし」「結果不明」の状態と対象注文IDを引き渡す。
- 商品明細の商品IDリンクからSCA-03（商品編集）へ遷移し、SCA-03の保存後・「一覧へ戻る」は既存仕様どおりSCA-02へ遷移する。ブラウザの戻る操作で本画面へ復帰した場合は、認証確認後に注文詳細を再取得する。
- タブ復帰時も処理中でなければ認証・注文詳細を再確認する。未保存の選択変更がある場合は勝手に上書きせず、背景で競合が判明した場合はAD17で通知して更新操作を止める。AD26による破棄確認後、最新情報の取得成功時だけ選択を置き換える。

- 復帰用の成功実績と未解決操作は別に保持する。一度成功した後で別の操作が失敗しても成功実績を消さない。未解決操作があれば結果不明を優先してSCA-04と連携する。
- 認証切れ・ログアウト・管理者切替時は表示・入力・復元キャッシュを破棄する。サーバー側の未解決操作記録は削除しない。
- 画面離脱・注文切替・認証切替前の古い応答で現在の画面を上書きしない。
- ブラウザ再読み込み・タブ閉鎖では、未保存変更の標準離脱警告を可能な範囲で利用する。表示・離脱阻止は保証しない。
- 操作結果・ローディング・エラーは支援技術でも認識できるよう通知する。
- 明細0件・重要な金額や基本情報の欠損・版情報や操作可否未確認の場合は、閲覧できる情報を残して更新・キャンセルを止め、再取得を案内する。欠損値を0円・現在日時で補完しない。
