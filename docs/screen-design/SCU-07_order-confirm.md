# SCU-07: 注文・決済確認画面

## 1. 基本情報

- **物理名:** `order-confirm`
- **対象:** ログイン済みユーザー。
- **目的:** 注文者・配送先・商品・最終請求額を確認し、クレジットカード決済を模したテスト注文を確定する。
- **遷移先:** SCU-08（注文完了）、SCU-06（カート）、SCU-03（ログイン）、SCU-05（マイページ）、SCU-01（商品一覧）。
- **共通画面:** CMN-01、CMN-02。
- **今回の方式:** カード決済と保存はモック。外部決済サービスへ接続せず、実際の請求は行わない。配送先保存と注文データの作成は実装する。
- **対象外:** 実カード情報の入力・保存、実決済・実返金、複数の保存配送先、海外配送、配送日時指定、ギフト、クーポン・ポイント。会員登録画面・マイページへの配送先編集追加。
- **記載範囲:** 表示、入力、操作、状態別文言、API連携項目。注文成立、在庫更新、二重注文防止、保存の内部処理は機能設計で定義する。
- **文言:** 要件定義にも記載し、API設計時に結果コード・表示条件と照合する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 共通レイアウト

- 上部にCMN-01、末尾にCMN-02、タイトルに「注文・決済確認」を表示する。
- 768px以上は左に入力・明細、右に請求額サマリー、768px未満は縦1列とする。
- タイトル付近と決済欄にO23を表示し、テスト用であることを明確にする。
- バッジは保存済みのカート数量を使用する。注文成立時はAPIの最新数量で更新し、0と決めつけない。

### 2.2 注文者・配送先

- 注文者氏名・メールアドレスは会員情報を参照表示し、変更しない。
- 保存済み配送先があれば初期値として表示する。保存先未登録と取得失敗を区別する。
- 保存済み配送先がない場合は空欄から入力する。受取人氏名のみ会員氏名を初期補完できる。
- 保存済み配送先取得失敗時はO24と再取得操作を表示する。手入力での注文は可能だが、保存状態を確認できるまで上書き保存は選択できない。

| 項目 | 条件・動作 |
| --- | --- |
| 受取人氏名 | 必須。前後の空白除去後1〜50文字。 |
| 郵便番号 | 必須。前後の空白と半角ハイフン除去後、半角数字7桁。数値型に変換しない。 |
| 都道府県 | 必須。国内の都道府県から選択。 |
| 市区町村・番地 | 必須。前後の空白除去後1〜100文字。 |
| 建物名・部屋番号 | 任意。前後の空白除去後100文字以内。 |
| 電話番号 | 必須。前後の空白と半角ハイフン除去後、半角数字10〜11桁。数値型に変換しない。 |
| この配送先を次回も使用する | 初期状態は未選択。選択時、注文成立後に会員の保存配送先1件を登録・上書きする。 |
| 上書き案内 | 保存先が既にある場合は「保存済みの配送先を今回の内容で更新します。」と表示する。 |

- 未選択でも今回の注文配送先として記録するが、次回用の保存配送先は変更しない。
- 保存先を変更しても過去の注文配送先を変更しない。
- 配送先を保存するための注文と無関係な操作は設けない。新規登録・上書きは本画面からの注文成立後に行う。
- 注文・保存処理中は入力を非活性とする。保存先の再取得で入力済みの内容を黙って上書きしない。

### 2.3 支払い方法（モック）

- 支払い方法は「クレジットカード（モック）」固定とする。
- カード番号・セキュリティコード・名義・有効期限の自由入力欄は設けない。
- システムが用意した架空の「テストカード」を選択する。実在カードとの紐付けは行わない。

| 要素 | 表示・動作 |
| --- | --- |
| 保存済みテストカード | 会員に保存済みの架空カードがあれば、テスト用表示名と模擬下4桁を表示して選択できる。 |
| 新しいテストカードを使用 | システム定義の架空カードを選択する。実カードを登録する操作ではない。 |
| 次回もこのテストカードを使用する | 新しいテストカード選択時のみ表示。初期状態は未選択。注文成立後に保存する。 |
| 保存を解除 | 保存済みの架空カードを次回用一覧から解除する。処理中は重複操作・注文操作を止める。 |
| 決済エラー | 模擬決済の失敗・結果不明を、注文成立と区別して表示する。 |

- 初期実装では保存済みテストカードは会員あたり1件とする。新しいものを保存する場合は上書きする。
- 保存済み情報の取得失敗時はO25と再取得操作を表示する。新しいテストカードによる保存なしの注文は可能とする。
- 保存解除は将来の再利用を止める操作であり、過去の注文・決済記録を削除しない。
- モックの成功・失敗・結果不明の切り替えは開発用設定等で行い、通常の注文画面には試験シナリオの選択欄を設けない。

### 2.4 注文商品・サマリー

- 明細は追加日時昇順・同一日時は明細ID昇順で参照専用表示する。数量変更・削除はSCU-06で行う。
- 商品画像、商品名、税込単価、保存済み数量、税込小計を表示する。画像取得失敗はNo Image、文字列はHTMLとして解釈しない。
- 金額はAPIの値を円単位・小数なし・3桁区切りで表示し、画面で計算しない。

| 項目 | 表示 |
| --- | --- |
| 商品合計（N点） | APIが返す数量合計・税込商品合計。 |
| 送料（税込） | 全国一律「￥500（税込）」。1注文につき1回。 |
| 決済手数料 | 「￥0」。利用者負担なし。 |
| 合計請求金額（税込） | 税込商品合計＋税込送料500円。表示額はAPIの値を使用する。 |
| 注文を確定する（テスト） | 明示的なボタン操作でテスト注文を送信する。 |
| カートへ戻る | SCU-06へ遷移する。注文処理中・結果確認中は非活性。 |

- 金額・数量・販売状態等が欠損または不正なら注文不可。「取得できません」と表示し0円で補完しない。
- 入力欄のEnterによる暗黙送信を行わない。キーボードによるボタン操作は可能とする。
- エラーは入力欄付近または全体通知に表示し、フォーカスを移す。状態変化を支援技術でも通知する。

## 3. 初期表示・アクセス制御

1. 認証確認中は個人情報・注文フォームを表示しない。通信失敗はO01と再読み込み。
2. 未ログイン・認証無効が確定した場合は、戻り先SCU-06としてSCU-03へ案内する。期限切れと判別可能な場合のみO21を引き継ぐ。
3. 未解決の注文操作がある場合は、新規注文の開始より結果確認を優先する。
4. 会員情報・カート・請求額・保存済み配送先・保存済みテストカードを取得する。
5. カートが空ならO02、在庫不足・販売不可・統合未完了ならO03とSCU-06への導線を表示し、注文不可とする。
6. 注文確認の必須情報取得失敗はO14。任意の保存情報だけの取得失敗は2章の個別制御に従う。
7. 通常表示時に注文操作の識別情報を準備する。再読み込みで未解決操作を新規扱いにしない。

## 4. アクション・イベント

### 4.1 注文確定

1. 配送先・テストカード選択を検証する。エラー時は送信しない。
2. 配送先、保存希望、テストカード識別情報、確認済みカート・金額の識別情報、注文操作識別情報を送信する。
3. 「注文処理中…」と表示し、入力・注文・戻る・保存解除を非活性にする。
4. バックエンドが返す結果に従い表示する。画面側だけで注文成功と判断しない。
5. 注文成立時は注文ID・注文番号をSCU-08へ引き継ぎ、最新カート数量でバッジを同期する。
6. 次回用の配送先・テストカード保存を希望していた場合は、注文成立後の保存結果を確認する。保存だけ失敗しても注文を再実行せず、SCU-08へO26を引き継ぐ。
7. 在庫不足・販売不可で未成立が確定した場合はO15とSCU-06への導線を表示する。
8. 価格・送料・明細の変更で未成立の再確認要求が返った場合は、最新内容とO16またはO17を表示する。入力は保持し、有効な状態なら明示的な再操作を受け付ける。
9. 模擬決済失敗で注文未成立が確定した場合はO27を表示する。入力を保持し、再検証したうえで安全に再試行できるようにする。
10. その他の未成立確定エラーはO18、項目エラーは当該項目へ表示する。

- 保存希望を付けただけで、成立前に次回用情報を更新しない。
- 試験データでも「決済成功・注文復旧中」と「未成立確定」を区別する。処理中・補償処理待ちを失敗確定と扱わない。
- 変更後の内容に対する再試行と、結果不明の同一操作照会を区別する。具体的な識別情報の管理は機能設計で定義する。

### 4.2 結果不明・再開

1. 注文確定の応答が確認できない場合は自動再送せず、O19を表示して元の操作識別情報で結果を照会する。
2. 注文成立が確認できた場合はSCU-08へ遷移する。
3. 未成立が確定し安全に再操作できる場合のみ、入力・注文操作を再開する。
4. 処理中・不明・照会失敗は注文ボタンを非活性のままとし、O20と「結果の再確認」「注文履歴を確認する」を表示する。
5. 注文履歴にないこと、照会が「該当要求なし」であることだけでは未成立を断定しない。APIが安全な再試行を許可する条件を機能設計で定義する。
6. 再読み込み・画面離脱後の再訪問・再ログイン後も、未解決操作の照会を再開できること。認証無効の場合は個人情報を非表示にし、再認証後に同じ会員の処理のみ再開する。

### 4.3 保存済みテストカードの解除

- 確認後に解除APIを実行する。対象はログイン会員の架空カードのみ。
- 成功時は一覧から除去してO28を表示し、選択中なら新しいテストカードの選択を求める。
- 失敗確定時はO29。結果不明はO30を表示し再取得する。状態不明のまま当該カードで注文を開始しない。
- 解除によって過去の注文記録を変更しない。

### 4.4 戻る・再同期・ログアウト

- カートへ戻る場合、同じ会員の同じ手続きで再表示できる範囲で配送先入力を保持する。カード番号等を保持する機能は設けない。
- タブ復帰時は処理中でなければ認証・カートを再検証する。入力中の配送先を背景取得で上書きしない。
- 対象操作の完了が確認できた状態で戻った場合はO22と注文確認の導線を表示し、再送しない。空カートだけで完了と断定しない。
- ログアウト・会員切替時は表示・入力を破棄する。未解決注文の識別・結果はバックエンド等で安全に維持し、他会員には見せない。

論理項目を列挙する。URL・メソッド・物理名・型・識別情報・結果コードはAPI設計で定義する。カード番号・セキュリティコードを受け取るAPIは設けない。

| 受信 | 注文ID・注文番号・最新カート数量 | SCU-08への遷移・バッジ。 |
| 受信 | 最新注文確認情報・変更箇所・理由 | 再確認、カート修正の案内。 |
| 受信 | 配送先／架空カードそれぞれの保存結果 | 注文成功と保存失敗の区別、O26の引き継ぎ。 |

- 保存を内部的に別処理・別APIとする場合も、注文成立後という順序と個別結果を維持する。注文再送で保存失敗を回復しない。

### 6.4 注文結果照会

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員認証情報・元の操作識別情報 | 同一操作の結果照会。 |
| 受信 | 成立済み／処理中／未成立確定／未確認、再操作可否 | 遷移・待機・再操作制御。 |
| 受信 | 注文ID・注文番号・カート数量・次回用保存結果 | SCU-08への復帰。 |
| 受信 | 失敗理由・最新確認情報（必要時） | 修正・再確認。 |

- 履歴一覧だけで結果照会を代替しない。「該当要求なし」時の安全性判定、照会間隔・打切り・再開方法は機能設計で定義する。

### 6.5 保存済みテストカード解除

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員認証情報 | 所有権確認。 |
| 送信 | 保存済み架空カードID | 解除対象。 |
| 受信 | 処理結果・エラー種別・最新保存状態 | 一覧・選択状態の更新、結果不明時の再確認。 |
