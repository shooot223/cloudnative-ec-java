# SCU-08: 注文完了画面

## 1. 基本情報

- **物理名:** `order-complete`
- **対象:** ログイン済みユーザー。
- **目的:** 本人のテスト注文の成立を通知し、注文番号・確定日時・税込総額・次回用情報の保存結果を表示する。
- **主な遷移先:** SCU-09（注文詳細）、SCU-05（マイページ）、SCU-01（商品一覧）、SCU-03（ログイン）。処理中・結果不明の場合はSCU-07の結果確認へ案内する。
- **共通画面:** CMN-01、CMN-02。共通ヘッダーのカート導線はSCU-06へ遷移する。
- **対象外:** 注文変更・キャンセル操作、次回用情報の再保存、領収書発行。
- **記載範囲:** 表示項目、操作、認証・再表示制御、文言、API連携項目。注文成立と在庫確保・減算の前後関係や非同期処理の内部仕様は機能設計で定義する。
- **文言:** 要件定義にも記載し、API設計時に結果コード・表示条件との対応を確認する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 共通レイアウト

- 上部にCMN-01、末尾にCMN-02を表示する。
- 完了確認後のタイトルは「ご注文完了」。確認中・取得失敗・処理中等では「注文情報の確認」とし、確認前に完了を断定しない。
- メインコンテンツは中央のパネルに配置し、狭い画面では左右余白を確保して縦1列とする。
- バッジはカート全体の最新の保存済み数量を表示する。0は非表示、100以上は「99+」。無条件に0にしない。
- 初回は同じ会員のSCU-07応答から得た数量を使用できる。再読み込み・再訪問・タブ復帰時は最新数量を取得する。
- カート取得失敗は数量不明として扱い、注文完了表示を妨げない。通知・再取得はCMN-01の共通仕様に従う。

### 2.2 注文完了情報

| 要素 | 表示・動作 |
| --- | --- |
| 完了メッセージ | 本人の注文成立を確認できた場合のみP01を表示する。 |
| テスト注意 | P02を表示する。実際の請求・発送があるような表現を用いない。 |
| 注文番号 | 利用者向け番号を表示する。成立は確認済みだが番号が欠損する場合はP10。実際に照会していない状態で「確認中」と表示しない。 |
| 注文確定日時 | 固定表示項目。APIの確定日時をJSTの「YYYY/MM/DD HH:mm」に整形する。欠損・不正時は「注文詳細からご確認ください」。 |
| 合計請求金額（税込） | 固定表示項目。注文確定時の税込総額を円単位・小数なし・3桁区切りで表示する。例：「￥6,440（税込）」。欠損・不正時は「注文詳細からご確認ください」。 |
| 詳細への案内 | P03を表示する。内部のキューや非同期処理名は表示しない。 |

- 金額は画面で再計算しない。現在の商品価格・保存配送先を用いて注文情報を作り直さない。
- 日時を現在日時、金額を0円で補完しない。

### 2.3 次回用情報の保存結果

- 見出し「次回用情報の保存結果」を表示し、配送先・テストカードを別々に表示する。
- 当該注文で保存を希望した項目だけを表示する。保存希望なしは表示しない。
- 表示対象は当該注文時の保存処理結果であり、現在の保存済み情報の有無ではない。後で保存先が変更・カードが解除されても過去の結果を書き換えない。

| 状態 | 表示・動作 |
| --- | --- |
| 成功 | 対象名を入れたP11を表示する。 |
| 失敗確定 | 対象名を入れたP04を警告として表示する。 |
| 処理中と確認できる | 対象名を入れたP12と「保存結果を再確認」を表示する。 |
| 結果不明・結果取得失敗 | 対象名を入れたP13と「保存結果を再確認」を表示する。失敗・成功と断定しない。 |
| 希望有無も取得できない | P14と「保存結果を再確認」を表示する。希望なしとして通知を隠さない。 |

- {対象}には「配送先」または「テストカード」を入れる。両方失敗した場合もそれぞれ状態を確認できること。
- 再確認は結果の読み取りのみ。保存処理・注文処理の再実行や再保存フォームは設けない。
- 保存結果が処理中・不明でも、注文成立が確認済みであれば完了メッセージと各画面への導線を利用できる。
- 成功表示も「この注文での保存結果」であると分かるよう表示する。保存済み配送先の全文やカード情報を追加表示する必要はない。

### 2.4 ナビゲーション

| 操作 | 動作 |
| --- | --- |
| 注文詳細を確認する | 確認済みの注文IDでSCU-09へ遷移する。注文IDを特定できない場合は非表示。 |
| マイページ（注文履歴）へ | SCU-05へ遷移する。未ログインの場合の制御は共通認証仕様に従う。 |
| 商品一覧へ戻る | SCU-01へ遷移する。取得失敗時も利用可能。 |
| 再読み込み | 対象の認証・注文情報を再取得する。注文確定を送信しない。 |
| 保存結果を再確認 | 対象注文の保存結果だけを再取得する。通信中は重複操作を防ぐ。 |

### 2.5 操作性

- 完了確認後は見出しまたは完了メッセージへフォーカスを移す。
- 保存結果の警告・結果更新・取得エラーを支援技術でも通知する。
- 全操作をキーボードで利用でき、色だけで成功・失敗を区別しない。
- 保存結果の再取得時は完了表示を残し、ページ先頭へ強制移動しない。

## 3. 認証・注文状態別の表示

| 条件 | 表示・遷移 |
| --- | --- |
| 認証確認中 | ローディング表示。個人情報・完了メッセージを表示しない。 |
| 未ログイン・認証無効確定 | 個人情報を非表示にし、戻り先SCU-05としてSCU-03へ遷移する。期限切れが判別できる場合のみP08を引き継ぐ。 |
| 認証確認通信失敗 | P05と再読み込み。未ログインと断定しない。 |
| 本人の成立済み注文・キャンセルされていない | 完了画面を表示する。独自の表示期限は設けない。 |
| 本人のキャンセル済み注文 | P16と「注文詳細を確認する」を表示する。P01は表示しない。 |
| 本人の処理中・結果不明の注文操作 | P15と「注文結果を確認する」を表示し、対象操作を引き継いでSCU-07の結果確認へ案内する。新規注文フォームは開始しない。 |
| 本人の未成立確定の注文操作 | P17とSCU-05・SCU-01への導線を表示する。P01は表示しない。 |
| 注文IDなし・完了対象を特定不可 | P07とSCU-05・SCU-01への導線を表示する。直近注文を推測して完了表示しない。 |
| 他会員の注文・不存在・不正な対象指定 | 共通のP06とSCU-05・SCU-01への導線。注文情報・存在有無の詳細を表示しない。 |
| 注文情報取得通信失敗 | P09と再読み込み・SCU-05への導線。注文失敗とは扱わない。 |

- URL・画面間で渡されたIDや文言だけでは成立・所有権を判断しない。
- 本人の成立済み注文かはバックエンドで確認する。初回のSCU-07応答を使用する場合も、同じ認証状態・同じ注文の確認済み応答であることを担保する。
- 再アクセスは直接アクセス・URL共有からのアクセスも含む。アクセス経路だけで表示を拒否しない。
- 保存結果が取得できないことは、注文成立確認の失敗とは区別する。

## 4. アクション・イベント

### 4.1 SCU-07からの正常遷移

1. SCU-07でバックエンドから成立済みと確認できた対象の情報を受け取る。画面遷移は履歴置換を基本とする。
2. 認証と本人の成立済み注文への対応を確認する。引き継ぎ情報で確認できない場合はAPIで取得する。
3. 3章に従い状態を分岐する。キャンセル済み等なら完了表示しない。
4. 成立確認後にP01・P02・P03、番号・日時・総額を表示し、保存結果を個別表示する。
5. カート数量を同期する。カート取得失敗だけで完了画面を消さない。
6. 当該注文の未送信配送先入力等の一時データを破棄する。完了済みの操作識別情報と結果確認に必要な関連付けは、二重注文防止・再表示のため適切に維持する。

### 4.2 再読み込み・再訪問・直接アクセス

1. 認証と対象の注文IDまたは完了手続きの識別情報を確認する。
2. 対象がなければP07。対象があれば最新の注文状態・所有権・成立情報を取得する。
3. 3章の分岐に従って表示し、表示期限切れという独自判定は行わない。
4. 当該注文時の保存希望・保存結果を取得し、再表示する。注文情報と別取得の場合も各結果を独立して扱う。
5. 最新のカート数量を取得する。
6. タブ復帰時も認証・注文状態・カートを再確認する。会員・注文が切り替わる前の古い応答を反映しない。

### 4.3 保存結果の再確認

1. 対象注文と認証情報を用い、保存結果を照会する。
2. 対象領域に「確認中…」を表示し、再確認ボタンを非活性にする。注文完了表示と導線は維持する。
3. 取得成功時は項目ごとの最新結果に切り替える。処理中であれば再確認操作を残す。
4. 取得失敗はP13またはP14とする。既知の過去の結果がある場合も最新確認に失敗したことを明示する。
5. 自動ポーリングは必須とせず、初期実装は手動再確認とする。保存処理を再送しない。

### 4.4 戻る操作・ログアウト

- SCU-07へ戻っても、SCU-07とバックエンドの同一操作の再実行防止を維持する。履歴置換だけに依存しない。
- ログアウト・会員切替時は注文番号・日時・金額・保存結果・復元用表示データを破棄する。
- ブラウザの戻る操作でも認証確認前に以前の個人情報を再表示しない。
- 本画面の表示・再取得では注文確定・模擬決済・次回用保存を実行しない。

- {対象}は「配送先」または「テストカード」。保存対象外は非表示。
- 日時・総額欠損時：「注文詳細からご確認ください」。
- 処理中：「読み込み中…」「確認中…」。P08はSCU-03へ引き継ぐ。
- 保存結果の通知は一時トーストではなく対象領域に表示する。

## 6. 画面で必要なAPI連携項目

以下は論理項目。専用API新設は必須とせず、SCU-07の確認済み応答・注文結果照会・SCU-09の詳細取得と共用できる。再表示時の成立・所有権・現在状態の確認を満たすこと。URL・項目名・型・エラーコードはAPI設計で確定する。

### 6.1 認証・注文完了情報取得／SCU-07からの引き継ぎ

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証・セッション情報 | ログイン確認、本人の注文へのアクセス確認。 |
| 送信・引き継ぎ | 注文ID、または対象手続き識別情報 | 注文・結果確認操作の特定。 |
| 受信 | 認証状態・処理結果・エラー種別 | ログイン遷移、対象不明、参照不可、通信失敗等の区別。 |
| 受信・引き継ぎ | 注文成立状態・現在の注文状況 | 完了表示、キャンセル案内、処理中、未成立等の分岐。 |
| 受信・引き継ぎ | 注文ID・注文番号 | 表示、SCU-09への遷移。 |
| 受信・引き継ぎ | 注文確定日時 | JSTで固定表示。タイムゾーンを判別できる形式で受け取る。 |
| 受信・引き継ぎ | 注文確定時の税込合計請求金額 | 固定表示。現在の商品価格で再計算しない。 |
| 受信・必要時 | 未解決操作の識別情報・結果確認への引き継ぎ情報 | SCU-07で元の操作の結果照会を再開する。 |

### 6.2 次回用情報の保存結果取得・再確認

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証情報 | 本人の処理結果取得。 |
| 送信 | 注文IDまたは保存処理に紐付いた手続き識別情報 | 当該注文時の保存結果を特定する。 |
| 受信・引き継ぎ | 配送先・テストカードそれぞれの保存希望有無 | 表示対象の判定。 |
| 受信・引き継ぎ | 項目別の結果（成功／失敗／処理中／不明／対象外） | 個別の通知。希望なしと取得失敗を区別する。 |
| 受信 | 取得結果・エラー種別 | 注文成立を維持したまま保存結果取得失敗を表示する。 |

- 現在の保存先の有無から当該注文の処理結果を推測しない。再訪問時も当該注文との対応を確認できる記録方式を機能設計で定義する。
