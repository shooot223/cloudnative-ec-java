# SCU-01: 商品一覧画面

## 1. 基本情報

- **物理名:** `product-list`
- **対象:** ユーザー（非会員・ゲストユーザーもアクセス可能）
- **目的:** 商品情報を取得し、一覧表示するトップページ。非会員でも商品の閲覧とカートへの追加が可能。
- **主な遷移先:** 商品詳細画面（SCU-03）、カート画面（SCU-04）
- **利用する共通画面:** CMN-01（ユーザー側共通レイアウト）、CMN-02（ユーザー側共通フッター）
- **記載範囲:** 画面構成、表示項目、入力、操作、画面状態、および画面から利用するAPIの連携項目。

## 2. 画面構成

### 2.1 共通エリア

- 画面上部にCMN-01を表示する。
- カートアイコン押下時はSCU-04へ遷移する。
- **バッジの集計方法:** カート内の全商品の数量合計を表示する。商品種類数ではない。
- **バッジの表示:** 合計0の場合は非表示、1〜99は数量、100以上は「99+」と表示する。
- バッジの数量は、カート取得・追加APIから返された最新の合計数量を使用する。
- 初回のカート取得失敗時は、未取得状態を数量0とみなさない。バッジは非表示とし、カート情報の取得失敗を通知する。

### 2.2 商品検索エリア

- テキスト検索欄と「検索」ボタンを表示する。
- 検索ボタン押下、または検索欄でのEnterキー操作により検索する。ただし、日本語入力の変換確定中は検索を実行しない。

| 項目 | 仕様 |
| --- | --- |
| 空欄検索 | 検索条件なしで一覧を取得する。空白除去後に空文字となった場合も同様とする。 |
| 入力値 | 前後の空白を除去する。空白除去後の最大文字数は50文字とする。 |
| 検索実行時 | 取得位置を先頭へ戻し、新しい結果を最大36件表示する。 |
| 追加取得時 | 実行済みの検索条件を引き継ぐ。検索欄の未確定の編集内容は使用しない。 |
| 検索結果0件 | 「条件に一致する商品がありません。」と表示する。 |
| 検索失敗時 | エラーメッセージと再試行操作を表示し、正常な0件と区別する。 |

- 前後の空白除去後に50文字を超えた場合は検索せず、入力欄の近くに「検索キーワードは50文字以内で入力してください。」と表示する。
- 検索欄の入力全体を1つの検索文字列として送信し、内部の空白は保持する。
- 入力した文字種を画面側で独自に変換しない。
- 価格・カテゴリの絞り込み欄は表示しない。

### 2.3 商品一覧エリア

- ページタイトル「商品一覧」を表示する。
- 商品カードをレスポンシブなグリッドレイアウトで表示する。
- APIが返す商品ID降順の一覧を、その順序で表示する。並び替え操作は設けない。

| 画面幅 | 1行の列数 |
| --- | --- |
| 768px未満 | 2列 |
| 768px以上・1024px未満 | 3列 |
| 1024px以上 | 6列 |

- **1回の取得件数:** 端末・画面幅を問わず最大36件。初回取得・検索・追加取得で共通とする。
- 画面幅の変更時はレイアウトのみ変更し、検索条件・取得済み商品・取得位置を保持する。
- 次の商品がある場合、一覧下部に「もっと見る」ボタンを表示する。
- ボタン押下時に次の商品を取得し、既存の一覧の末尾に追加する。
- 累計表示件数は36件を超えてよい。
- スクロールによる自動取得は行わない。
- 次の商品がない場合は「もっと見る」ボタンを非表示にする。
- 1件以上の商品を全件表示した場合は「すべての商品を表示しました。」と表示する。検索中は検索条件に一致する全件を指す。

### 2.4 商品カード

| 要素 | 表示・動作仕様 |
| --- | --- |
| 商品ID | 画面には表示せず、詳細遷移・カート追加時の識別情報として保持する。hidden要素の使用は必須としない。 |
| 商品画像 | APIが返す画像URLを参照する。画像の縦横比を保持し、カード内の所定領域に表示する。 |
| 代替画像 | 画像URLが未設定、または画像取得に失敗した場合はNo Image画像を表示する。代替画像への切り替えを繰り返さない。 |
| 商品名 | 先頭20文字まで表示し、20文字を超える場合は末尾に「...」を付ける。 |
| 商品概要 | 先頭30文字まで表示し、30文字を超える場合は末尾に「...」を付ける。未設定時は空欄とする。 |
| 価格 | 円単位・小数なし・3桁区切りで税込価格を表示する。例：「￥1,980（税込）」。 |
| カートに追加ボタン | 在庫が1以上で販売可能な場合に表示する。1回の追加数量は1とする。 |
| 売り切れ表示 | 在庫が0の場合は「売り切れ」と表示し、追加ボタンは表示しない。商品詳細への遷移は可能とする。 |
| その他の販売不可 | 公開中でも販売停止などの場合は「現在購入できません」と表示し、追加ボタンは表示しない。 |

- 省略時の「...」は商品名20文字・商品概要30文字の制限に含めない。制限文字数ちょうどの場合は付けない。
- カート追加ボタン以外の商品カード領域を押下すると、対象商品のSCU-03へ遷移する。
- 詳細リンクと追加ボタンは独立した操作要素とし、追加操作による詳細遷移を防ぐ。
- 商品画像には商品名などの代替テキストを設定する。
- 詳細遷移、検索、追加取得、カート追加はキーボードでも操作できること。
- 画像領域の寸法・余白などの見た目の詳細は、UI実装時に定義する。

### 2.5 フッター

- 商品一覧エリアおよび「もっと見る」ボタンの後にCMN-02を表示する。
- 商品を追加取得しなくてもフッターを操作できること。

## 3. アクション・イベント

### 3.1 初回表示時

1. カート取得APIで現在の利用者のカート合計数量を取得し、CMN-01のバッジを更新する。
2. 商品一覧APIを呼び出し、商品一覧エリアにローディングスピナーを表示する。
3. 商品取得成功時は一覧、または空状態のメッセージを表示する。
4. 商品取得失敗時はエラーメッセージと「再読み込み」ボタンを表示する。

- 商品一覧とカート情報は独立して取得する。カート取得失敗によって商品一覧の表示を停止しない。
- ゲストにカートが存在しない場合は正常な空カートとして扱う。
- カート取得に失敗した場合は、カート情報を再取得できる操作を提供する。

### 3.2 検索実行時

1. 入力値の前後の空白を除去し、入力チェックを行う。
2. 検索条件を確定し、取得位置・追加取得エラーをリセットする。
3. 以前の一覧は非表示にし、一覧エリアにローディング表示を出す。「もっと見る」は表示しない。
4. 商品一覧APIに検索条件を渡し、先頭から最大36件を取得する。
5. 成功時は新しい一覧へ置き換える。検索条件ありで0件の場合は検索結果0件のメッセージを表示する。
6. 失敗時は検索エラーと「再試行」ボタンを表示する。再試行では失敗した検索条件で先頭から取得する。

- 検索ボタンは検索処理中に非活性とし、重複送信を防ぐ。
- 条件変更前の追加取得など、古い応答が現在の検索結果に混ざらないようにする。

### 3.3 「もっと見る」ボタン押下時

1. 次の商品があり、追加取得中でない場合に限り、実行済み検索条件と継続情報で次のデータを要求する。
2. 取得中は既存の商品を残し、ボタンを非活性にして「読み込み中…」と表示する。
3. 成功時は商品を一覧の末尾に追加する。同一の商品IDは重複表示しない。
4. 失敗時は既存の商品を残し、一覧下部にエラーを表示する。ボタンを「再試行」に切り替える。
5. 再試行では失敗した続きのデータを取得する。成功するまで取得位置を進めない。
6. 成功後、次の商品がある場合は「もっと見る」に戻し、ない場合はボタンを非表示にする。

- 次のデータの有無はAPIの継続情報で判定する。
- 画面離脱後や検索条件変更後の古い応答は表示に反映しない。

### 3.4 商品カード押下時

- 商品IDを使用してSCU-03へ遷移する。
- 遷移先で商品が削除済み・非公開となっていた場合の表示はSCU-03で定義する。
- ブラウザの戻る操作時は、可能な範囲で検索条件・入力欄・取得済み一覧・継続情報・スクロール位置を復元する。
- 一覧を復元できない場合は、保持できている検索条件で先頭から再取得する。検索条件も復元できない場合は条件なしで取得する。
- 一覧の復元時もカート数量は再取得する。

### 3.5 「カートに追加」ボタン押下時

1. 詳細画面へ遷移させず、対象商品の追加処理を開始する。
2. 対象ボタンを非活性にして、連打による重複送信を防ぐ。
3. カート追加APIに商品IDと追加数量1を送信する。
4. 応答を受け取り、成功の場合は「カートに追加しました」と表示し、返された合計数量でバッジを更新する。
5. 追加不可・エラーの場合は、結果に応じたメッセージを表示する。成功通知は出さず、画面側で数量を加算しない。
6. 最新の商品状態が返された場合はカードへ反映する。在庫0は売り切れ、販売停止は購入不可、非公開・削除済みは一覧から除外する。
7. 処理終了後、追加可能な商品のボタンを再び操作可能にする。

- 応答順の逆転でバッジが古い値に戻らないようにする。
- タイムアウトなどで更新結果が不明な場合は、結果不明のメッセージとSCU-04への導線を表示し、カート情報を再取得する。再取得した合計数量だけで当該追加の成功を断定しない。
- 追加APIを無条件で自動再送しない。
- 成功トーストは3秒、エラートーストは5秒を目安とし、支援技術でも認識できるようにする。再試行操作や結果不明の案内は、操作できる状態で残す。

### 3.6 カート表示の再取得

- 別タブから本画面へ戻った際などにカート情報を再取得し、バッジを更新する。
- ログイン・ログアウト後に本画面を表示する場合は、その時点のカート情報でバッジを更新する。
- カートなし・期限切れなどによりAPIが空カートを返した場合は、バッジを非表示にする。
- ログイン時の統合結果の通知UIはログイン画面・共通レイアウトの設計で扱う。

## 4. 入力・表示制御と状態定義

### 4.1 入力・表示制御

- 検索キーワードは前後の空白を除去して50文字以内とし、超過時は送信しない。
- 商品名・商品概要はテキストとして表示し、含まれるHTMLを実行しない。
- 在庫情報や販売可否が欠損・不正な場合は追加ボタンを操作不可とし、「現在カートに追加できません。」と表示する。
- 税込価格はAPIから受け取った値を表示形式に整形し、画面側で税額計算しない。

### 4.2 状態・メッセージ一覧

| 状態 | 表示・動作 |
| --- | --- |
| 初回取得中・検索中 | 商品一覧エリアにローディング表示を出す。 |
| 条件なしで取得成功・0件 | 「現在表示できる商品がありません。」と表示する。 |
| 検索条件ありで取得成功・0件 | 「条件に一致する商品がありません。」と表示する。 |
| 初回取得失敗 | 「商品情報の取得に失敗しました。」と「再読み込み」を表示する。 |
| 検索失敗 | 「商品の検索に失敗しました。」と「再試行」を表示する。 |
| 検索文字数超過 | 「検索キーワードは50文字以内で入力してください。」と表示する。 |
| 追加取得中 | 既存の商品を残し、ボタンを非活性にして「読み込み中…」と表示する。 |
| 追加取得失敗 | 「続きの商品を取得できませんでした。」と「再試行」を表示する。 |
| 全件取得完了 | 「もっと見る」を非表示にする。1件以上なら「すべての商品を表示しました。」と表示する。 |
| カート取得失敗 | 「カート情報の取得に失敗しました。」と再取得操作を表示する。商品閲覧は継続可能とする。 |
| カート追加成功 | 「カートに追加しました」と表示し、バッジを更新する。 |
| 在庫不足 | 「在庫数を超えるため、追加できません。」と表示する。 |
| 販売終了・非公開・削除済み | 「この商品は現在カートに追加できません。」と表示する。 |
| カート追加失敗が確定 | 「カートに追加できませんでした。時間をおいて再度お試しください。」と表示する。 |
| カート更新結果不明 | 「追加結果を確認できませんでした。カートをご確認ください。」と表示し、カート情報を再取得する。 |
| 画像取得失敗 | 当該画像のみNo Imageへ切り替える。画面全体をエラーにしない。 |

## 5. 画面で必要なAPI連携項目

画面が送受信する論理項目のみを列挙する。URL、HTTPメソッド、正式項目名、型、認証方式および内部処理はAPI設計で定義する。

### 5.1 商品一覧取得・検索・追加取得

| 方向 | 項目 | 画面での用途 |
| --- | --- | --- |
| 送信 | 検索キーワード | 前後の空白除去後50文字以内。空欄は条件なしとして送信する。 |
| 送信 | 取得件数 | 最大36件。API側で固定の場合は省略可能。 |
| 送信 | 継続情報 | 初回・検索時は先頭、追加取得時は直前の応答で受け取った情報を渡す。 |
| 受信 | 商品配列 | APIが返す順序で表示する。空配列は0件表示に使用する。 |
| 受信・商品ごと | 商品ID | 詳細遷移、カート追加、重複表示の判定。 |
| 受信・商品ごと | 商品名 | カード表示。 |
| 受信・商品ごと | 商品概要 | カード表示。未設定可。 |
| 受信・商品ごと | 商品画像URL | 画像表示。未設定・取得失敗時は代替画像へ切り替える。 |
| 受信・商品ごと | 税込価格 | 円単位・小数なし・3桁区切りで表示。 |
| 受信・商品ごと | 在庫数 | 売り切れと追加ボタンの表示判定。 |
| 受信・商品ごと | 販売可否・表示用理由 | 販売停止などの表示と追加ボタンの制御。 |
| 受信 | 次の商品があるか | 「もっと見る」の表示判定。 |
| 受信 | 次回取得用の継続情報 | 次の商品取得に使用。 |

- 商品総件数は画面に表示しないため、必須の受信項目としない。

### 5.2 カート数量取得

| 方向 | 項目 | 画面での用途 |
| --- | --- | --- |
| 共通送信情報 | 認証・ゲスト識別に必要な情報 | 共通のAPI呼出し方式に従って連携する。画面の入力項目としては設けない。 |
| 受信 | カート内合計数量 | カートバッジの表示。0は非表示。 |
| 受信・採用時 | 更新状態を識別する情報 | 古い応答によるバッジ上書き防止。項目の要否・形式はAPI設計で確定する。 |

### 5.3 カート追加

| 方向 | 項目 | 画面での用途 |
| --- | --- | --- |
| 共通送信情報 | 認証・ゲスト識別に必要な情報 | 共通のAPI呼出し方式に従って連携する。 |
| 送信 | 商品ID | 押下したカードの商品を指定。 |
| 送信 | 追加数量 | 常に1を送信。 |
| 受信 | 処理結果・結果コード・理由 | 成功、在庫不足、販売不可などの通知と画面更新。 |
| 受信・成功時 | 対象商品ID・更新後数量 | 追加結果の識別。 |
| 受信・成功時 | カート内合計数量 | バッジの更新。 |
| 受信・取得できた場合 | 最新の在庫数・販売可否・表示可否 | 売り切れ・販売停止の表示更新、カード除外。 |
| 受信・採用時 | 更新状態を識別する情報 | 古い応答によるバッジ上書き防止。項目の要否・形式はAPI設計で確定する。 |

- 商品名・価格・画面側で計算した追加後数量は、追加リクエストの必須項目にしない。
- 通信失敗時は応答項目がない場合もあるため、通信エラーとして表示する。

### 5.4 エラー表示に必要な情報

- エラーコード、画面で表示する理由、入力エラーの対象項目。
- 再試行の可否など、画面の操作制御に必要な情報。
- 更新結果が不明な場合は、結果不明の案内とカートへの導線を表示する。
