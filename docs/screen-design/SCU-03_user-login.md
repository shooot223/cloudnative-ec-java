# SCU-02: ユーザーログイン画面設計書

## 1. 基本情報

- **物理名:** `user-login`
- **対象:** 未ログイン・ゲストユーザー
- **画面の役割:** メールアドレス・パスワードを入力し、認証結果に応じて遷移・案内を行う独自ログイン画面。
- **主な遷移先:** 有効な遷移元画面（SCU-01、SCU-02、SCU-06など）、新規会員登録画面の登録／メール確認ステップ（画面ID未採番）。
- **戻り先不明時:** 商品一覧画面（SCU-01）。
- **共通画面:** CMN-01（ユーザー側共通レイアウト）、CMN-02（ユーザー側共通フッター）。
- **記載範囲:** 表示、入力、操作、状態、遷移、画面で必要なAPI連携項目。
- 認証方式、セッション期限の判定、Cognito連携、カート統合の内部処理は共通認証・共通カート仕様で扱う。
- SCU-03は商品詳細画面とし、マイページのIDとして使用しない。

## 2. 画面構成

### 2.1 共通エリア

- 上部にCMN-01を表示する。
- 認証状態が未確定の間は、認証状態に依存するユーザーメニューを確定表示しない。
- 未ログイン確認後はCMN-01の未ログイン時表示を適用する。
- ログイン完了後はCMN-01のログイン時表示へ更新する。
- カート数量はAPIの値で表示する。取得失敗を数量0とみなさない。

### 2.2 ログインフォーム

- ページタイトル「ログイン」を表示する。
- フォームをカード状に配置し、PCでは横方向の中央、スマホでは左右に余白を設けて表示する。
- 縦方向は内容量に応じてスクロール可能とし、ソフトウェアキーボード表示中も項目・ボタンへアクセスできるようにする。

| 要素 | 表示・操作 |
| --- | --- |
| メールアドレス | 常時表示するラベルと入力欄を配置。プレースホルダー例：`user@example.com`。 |
| パスワード | 常時表示するラベルとパスワード入力欄を配置。初期状態は伏字。 |
| パスワード表示切替 | 入力欄の右端に配置。「表示する／非表示にする」を切り替える。入力内容を保持し、フォーム送信は行わない。 |
| ログインボタン | 通常は「ログイン」。認証中は非活性として「ログイン処理中…」と表示。 |
| 新規会員登録リンク | フォーム下部に「新規会員登録」を表示。登録画面へ遷移。 |
| フォームエラー | フォーム上部に認証・通信エラーを表示。 |
| 項目エラー | 該当項目の下部に表示。 |
| 案内メッセージ | 登録完了、セッション期限切れ、メール未確認などの案内に使用。 |

- パスワード再設定リンクは表示しない。
- ログイン状態を保持する期間の選択欄は設けない。
- 入力ラベルと入力欄を関連付け、キーボード操作・パスワードマネージャー・貼り付けに対応する。
- メール欄はログイン名としての自動入力、パスワード欄は現在のパスワードの自動入力に対応する。
- 表示切替ボタンは操作内容と現在の状態を支援技術でも認識できるようにする。
- エラーは赤色だけでなく文章で伝え、送信時の入力エラーは最初の該当項目へフォーカスを移す。

### 2.3 認証後のカート確認エリア

- 認証成功後はログインフォームを非表示とし、「カートを確認しています…」と表示する。
- 統合失敗時は「ログインしましたが、カートを統合できませんでした。」と表示し、次の操作を設ける。
  - 「カート統合を再試行」：認証情報を再入力させず統合処理のみ再試行する。
  - 「元の画面へ進む」：有効な戻り先へ遷移する。
- 統合による数量調整・除外がある場合は、対象商品、調整後数量または除外理由を表示し、「元の画面へ進む」を表示する。
- 統合失敗・結果不明をカートが空になったという表示に置き換えない。
- 「元の画面へ進む」で離脱した後も、共通カート側で未解決の統合状態を保持し、SCU-04で案内・再試行できるよう連携する。SCU-04側の配置は同画面の設計で定義する。

### 2.4 フッター

- メインコンテンツの後にCMN-02を表示する。
- 内容の長さに応じてページ全体をスクロールできるようにする。

## 3. 入力・表示制御

| 項目 | 制御 | エラーメッセージ |
| --- | --- | --- |
| メールアドレス | 前後の空白を除去。空欄は不可。 | 「メールアドレスを入力してください。」 |
| メールアドレス | メールアドレスとしての基本的な形式を検証。登録側と同じ判定を使用する。 | 「メールアドレスの形式で入力してください。」 |
| パスワード | 未入力は不可。空白の除去、大小文字・文字種の変換を行わない。 | 「パスワードを入力してください。」 |

- メールアドレスは前後の空白除去以外に画面側で独自の正規化をしない。
- メールアドレス・パスワードの入力上限は新規会員登録・共通認証仕様と揃える。具体値はそれらの設計時に確定し、無断で切り詰めない。
- ログイン画面では新規登録用のパスワード強度チェックを行わない。
- 入力エラーがある場合はAPIを呼び出さない。
- 認証中は入力欄、ログインボタン、新規会員登録リンクの操作を停止し、二重送信や処理途中の意図しない遷移を防ぐ。
- 認証失敗が確定した場合はメールアドレスを保持し、パスワードをクリアして再入力できる状態に戻す。
- パスワードはURL、ローカルストレージ、セッションストレージ、画面遷移情報に保存しない。成功・画面離脱時は入力値を破棄する。
- 古い応答や離脱後の応答で画面を更新しない。

## 4. アクション・イベント

### 4.1 初期表示

1. 遷移元情報と、登録完了・セッション期限切れなどの案内情報を取得する。
2. 認証状態確認APIを呼び出し、確認中表示を出す。確認が完了するまでログイン送信を許可しない。
3. 未ログインの場合は入力フォームを表示する。
4. ログイン済みの場合は有効な戻り先へ遷移する。ただし、未解決のカート統合を処理中・案内中である場合は、その画面状態を優先し自動遷移しない。
5. 認証状態の確認に失敗した場合はエラーと「再試行」を表示する。通信失敗を未ログインとして扱わない。

- 登録完了後は「会員登録が完了しました。ログインしてください。」と表示する。
- 期限切れによる遷移では「ログインの有効期限が切れました。再度ログインしてください。」と表示する。
- 登録画面から安全に引き継げる場合はメールアドレスを入力済みにする。パスワードは引き継がない。

### 4.2 ログインボタン押下・Enterキー操作

1. 日本語入力の変換確定中は送信しない。それ以外ではボタン押下とEnterを同じ処理とする。
2. 入力チェックを行い、エラーがあれば項目下部に表示する。
3. エラーがなければ重複送信を防止し、認証APIへメールアドレスとパスワードを送信する。
4. 認証結果ごとに次の処理を行う。

| 結果 | 動作 |
| --- | --- |
| 認証成功 | パスワードを破棄し、CMN-01をログイン状態へ更新。カート確認へ進む。 |
| メール確認が必要 | 「メールアドレスの確認が完了していません。」と「メール確認へ進む」を表示。本人の確認手続きを継続するための情報と戻り先を引き継ぐ。 |
| 認証失敗 | 共通の認証失敗メッセージを表示し、再入力可能にする。 |
| 試行回数制限 | 一時制限のメッセージを表示。再試行可能時刻などがあれば、その情報に従って操作を制御する。 |
| サーバーエラー | サーバーエラーのメッセージを表示し、再操作可能にする。 |
| 通信切断・タイムアウト | 認証結果が不明な案内を表示し、認証状態を再確認する。無条件でログインAPIを再送しない。 |

- 認証状態の再確認でログイン済みならカート確認へ進み、未ログインが確定すればフォームを再操作可能にする。確認自体が失敗した場合は「再試行」を表示する。
- メール確認が必要な応答は、共通認証APIが案内可能と判断した場合にのみ表示する。メールの存在確認だけを目的とする呼出しは行わない。
- 追加認証が必要な状態を認証成功とみなさない。今回の設定で発生させる追加認証の範囲は共通認証設計で確定する。

### 4.3 カート統合・確認

1. 認証成功後、ゲストカートの統合結果を確認する。ログインAPIが結果を返さない構成では、共通カートAPIを呼び出す。
2. 処理中は「カートを確認しています…」と表示する。
3. 成功または統合不要の場合は、最新の合計数量でバッジを更新する。
4. 調整・除外がなければ有効な戻り先へ自動遷移する。
5. 調整・除外があれば内容と「元の画面へ進む」を表示する。
6. 統合失敗の場合は認証状態を維持し、失敗案内と再試行・戻り先への操作を表示する。
7. 通信断などで結果が不明な場合は統合結果を確認する。結果を確認できない場合も再ログインは要求しない。

- 統合再試行中は再試行ボタンを非活性にする。追加の統合要求を重複送信しない。
- 統合結果の確認・再試行に必要な情報は共通APIを通じて引き継ぐ。画面側で明細の数量合算や在庫調整を行わない。
- 統合再試行時に認証期限切れが返された場合は、パスワードを破棄し、再ログインの案内とフォームを表示する。戻り先と未解決の統合状態は共通仕様に従って保持する。

### 4.4 新規会員登録・メール確認への遷移

- 「新規会員登録」押下時は登録画面へ遷移し、元の戻り先を引き継ぐ。
- メール未確認の案内からは、登録画面の確認コード入力ステップへ遷移する。
- 確認コードの送信・入力・再送・エラーの詳細は登録画面の設計に記載する。
- 確認完了後はSCU-02へ戻る。自動ログインは行わず、元の戻り先を保持したままログイン入力を受け付ける。
- 登録・メール確認を途中で中止して戻った場合は、完了メッセージを表示しない。

### 4.5 戻り先の扱い

- 戻り先はアプリ内の許可された画面とする。
- 戻り先がない、不正、外部URL、ログイン・登録などの認証画面自身である場合はSCU-01へ遷移する。
- ログイン完了後は戻る操作で完了済みログインフォームに戻りにくい遷移方式を使用する。
- 戻り先には画面表示に必要な情報のみ保持し、パスワードや認証トークンを含めない。

## 5. 状態・メッセージ一覧

| 状態 | 表示 | 操作 |
| --- | --- | --- |
| 認証状態確認中 | 「ログイン状態を確認しています…」 | ログイン送信不可。 |
| 認証状態確認失敗 | 「ログイン状態を確認できませんでした。」 | 「再試行」を表示。 |
| 登録完了後 | 「会員登録が完了しました。ログインしてください。」 | ログイン可能。 |
| セッション期限切れ | 「ログインの有効期限が切れました。再度ログインしてください。」 | ログイン可能。 |
| 認証処理中 | 「ログイン処理中…」 | 入力・送信を非活性。 |
| 認証失敗 | 「メールアドレスまたはパスワードが間違っています。」 | 再入力可能。 |
| メール未確認 | 「メールアドレスの確認が完了していません。」 | 「メール確認へ進む」を表示。 |
| 試行回数制限 | 「試行回数が上限に達しました。時間をおいて再度お試しください。」 | APIの制限情報に従う。 |
| サーバーエラー | 「ログイン処理に失敗しました。時間をおいて再度お試しください。」 | 再操作可能。 |
| 通信失敗・結果不明 | 「ログイン結果を確認できませんでした。ログイン状態を確認しています。」 | 状態再確認。失敗時は再試行。 |
| カート統合中 | 「カートを確認しています…」 | 重複操作不可。 |
| カート数量調整・除外あり | 「カートの商品を調整しました。内容をご確認ください。」と明細 | 「元の画面へ進む」を表示。 |
| カート統合失敗 | 「ログインしましたが、カートを統合できませんでした。」 | 「カート統合を再試行」「元の画面へ進む」を表示。 |
| カート統合結果不明 | 「ログインしましたが、カートの統合結果を確認できませんでした。」 | 結果確認・安全な再試行と戻り先への操作を提供。 |

- 認証失敗はID不存在とパスワード誤りで文言を分けない。
- エラー・統合調整内容は、利用者が読めるよう自動消去しない。
- 生のCognito例外や内部エラー情報をそのまま表示しない。

## 6. 他画面・共通機能との連携

| 連携先 | 内容 |
| --- | --- |
| CMN-01 | 認証状態・必要なユーザー表示情報・最新のカート合計数量を反映する。 |
| 新規会員登録画面（ID未採番） | 登録、確認コード入力・再送、確認後のSCU-02復帰、戻り先の引継ぎ。 |
| SCU-04 | 未解決のカート統合の通知・再試行。配置と操作はSCU-04で定義する。 |
| 共通認証機能 | 認証状態確認、ログイン、期限切れ判定、再認証への案内。 |
| 共通カート機能 | 統合結果確認・再試行、数量調整・除外通知、バッジ更新。 |

- 新規会員登録画面のID、入力上限値などは該当設計との整合を取って確定する。
- 認証・統合処理が必要とする内部方式や有効期限設定は、本画面設計には記載しない。

## 7. 画面で必要なAPI連携項目

後続API設計用の論理項目。URL、メソッド、正式項目名、型、必須条件はAPI設計時に確定する。以下の区分ごとに独立したエンドポイントを作成することを必須とはしない。

### 7.1 認証状態確認

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 共通送信 | セッション識別に必要な情報 | 共通API呼出し方式に従う。フォーム入力項目にはしない。 |
| 受信 | 認証状態 | ログイン済み／未ログイン／期限切れの判定。通信失敗とは区別する。 |
| 受信・必要時 | ユーザー表示情報 | CMN-01にユーザー名等を表示する場合に使用。パスワード等は含めない。 |
| 受信・必要時 | セッション有効期限 | 期限切れ表示や状態更新に用いる場合の候補。画面の時刻だけで認証可否を確定しない。 |

### 7.2 ログイン

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信 | メールアドレス | 前後の空白除去後の値。 |
| 送信 | パスワード | 変換せずHTTPS経由で送信。保存・URLへの付与をしない。 |
| 共通送信 | ゲスト識別・リクエスト保護に必要な情報 | カート引継ぎ等に使用。共通API方式に従う。 |
| 受信 | 認証結果・結果コード | 成功、認証失敗、メール確認必要、一時制限などの表示分岐。 |
| 受信・必要時 | 次に必要な操作・確認手続き継続用情報 | メール確認ステップへの案内に使用。必要最小限とする。 |
| 受信・必要時 | ユーザー表示情報 | ヘッダー更新。 |
| 共通連携 | セッション確立情報 | Cookie等の共通認証方式で扱う。画面がダミートークンを保存する処理は設けない。 |
| 受信・同時処理時 | カート統合結果・最新合計数量 | 統合をログイン処理内で行う構成の場合のみ。詳細は7.3。 |

### 7.3 カート統合結果確認・再試行・数量取得

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 共通送信 | 認証情報・ゲストカートとの関連を識別する情報 | 共通方式に従って処理対象を識別。任意の会員IDを画面から指定しない。 |
| 送信・必要時 | 統合処理識別子 | 同じ統合の確認・再試行に使用する場合の候補。API設計で確定。 |
| 受信 | 統合状態 | 処理中、成功、統合不要、失敗、結果不明等を区別。 |
| 受信 | 結果コード・理由 | エラー・案内表示。 |
| 受信・取得できた場合 | カート内合計数量 | バッジ更新。未取得は0扱いにしない。 |
| 受信・調整時 | 商品ID、表示可能な商品名、調整後数量、調整理由 | 数量調整の明細表示。 |
| 受信・除外時 | 商品ID、表示可能な商品名、除外理由 | 除外の明細表示。 |
| 受信 | 再試行可否・結果確認に必要な情報 | 再試行・確認操作の制御。 |

- 画面からローカルストレージのカート明細を送信する方式は使用しない。
- ログイン済みでもカート統合が失敗する結果を表現できること。

### 7.4 共通エラー・制御情報

- 画面表示用の結果コード・理由、入力エラー対象項目。
- 一時制限時の再試行可能時刻または待機時間（取得できる場合）。
- 通信失敗、認証失敗、セッション期限切れ、追加手続き必要、統合失敗の区別。
- 未確認メールの案内に必要な情報は、共通認証仕様で許可された範囲に限定する。
- 戻り先は認証トークンと分離した画面遷移情報として保持する。サーバーと連携する場合もアプリ内の許可された戻り先として検証する。
