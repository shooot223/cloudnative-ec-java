# SCU-05: マイページ画面

## 1. 基本情報

- **物理名:** `my-page`
- **対象:** ログイン済みユーザー。
- **目的:** 自分の会員情報・注文履歴を確認し、注文詳細へ遷移する。
- **主な遷移先:** SCU-09（注文詳細）、SCU-01（商品一覧）、SCU-03（ユーザーログイン）、SCU-06（カート）。
- **共通画面:** CMN-01（ユーザー側共通レイアウト）、CMN-02（ユーザー側共通フッター）。
- **記載範囲:** 画面構成、表示・操作、状態別文言、画面で必要なAPI連携項目。注文の成立判定・状態遷移・金額計算・所有権検証の内部処理は要件定義・機能設計で扱う。
- **対象外:** 会員情報変更、退会、注文履歴の検索・絞り込み・並び替え。
- **文言の扱い:** 文言を要件定義にも記載し、API設計時に結果コード・表示条件との対応を再確認する。文言IDは資料間の参照用であり、APIエラーコードではない。

## 2. 画面構成

### 2.1 共通エリア

- 上部にCMN-01、メインコンテンツの後にCMN-02を表示する。
- カートアイコン押下時はSCU-06へ遷移する。
- カートバッジは全商品の数量合計。0は非表示、100以上は「99+」とする。
- カート情報取得失敗は数量不明として扱い、0件と断定しない。マイページの閲覧は継続できる。通知・再取得はCMN-01の共通仕様に従う。

### 2.2 会員情報エリア

- ページタイトル「マイページ」を表示する。
- 氏名とメールアドレスを参照専用で表示する。編集フォームは設けない。
- 「お買い物を続ける」リンクを表示し、SCU-01へ遷移する。会員情報取得失敗時も利用できる。
- 氏名・メールアドレス等の文字列はテキストとして表示し、HTMLを実行しない。

### 2.3 注文履歴エリア

- 見出し「注文履歴」を表示する。
- 1注文につき1カードとし、縦方向の一覧で表示する。狭い画面ではカード内の項目を縦に配置する。
- 表示対象は、注文機能の定義上成立した自分の注文。キャンセル済みも表示する。カート・注文入力途中・注文作成前の失敗は表示しない。
- APIから受け取った注文日時降順・同一日時の場合は注文ID降順の順序で表示する。
- 初回・追加取得とも最大20件を取得する。
- 次の履歴があれば「もっと見る」を表示する。スクロールによる自動取得は行わない。
- 次の履歴がなければボタンを非表示にする。1件以上ならM06、0件ならM02のみ表示する。初回取得で全件取得した場合も同様とする。

### 2.4 注文カード

| 項目 | 表示・動作仕様 |
| --- | --- |
| 注文ID | 詳細遷移・重複排除に使用する識別情報として保持する。 |
| 注文番号 | 利用者向けの注文番号を表示する。注文IDと同一値とするかはAPI設計で確定する。 |
| 注文日時 | APIの注文確定日時をJSTで「YYYY/MM/DD HH:mm」に整形する。例：「2026/10/02 15:30」。 |
| 注文状況 | 共通の対応表に従う利用者向け表示名を表示する。色だけで区別しない。内部状態名は直接表示しない。未定義・欠損時はM08を表示する。 |
| 合計金額 | 注文確定時の税込総額を「￥5,940（税込）」の形式で表示する。円単位・小数なし・3桁区切り。送料・手数料・割引を反映したAPIの値を使用し、画面で再計算しない。 |
| 代表商品名 | 注文明細の先頭商品の注文時点の商品名を表示する。先頭30文字まで表示し、超過時のみ末尾に「…」を付ける。省略記号は30文字に含めない。 |
| 商品点数 | 注文時点の明細数量合計を使用し、「商品名／合計N点」と表示する。商品種類数ではない。 |
| 詳細を見る | 対象の注文IDを用いてSCU-09へ遷移する。 |

- キャンセル・返金後も注文確定時の総額を保持して表示する。返金情報はSCU-09で扱う。
- 商品の改名・削除後も、注文時点の商品名を表示する。
- 商品名が取得できない場合は「商品情報を取得できません」と表示する。金額・日時・数量が欠損または不正な場合は「取得できません」とし、0や現在日時で補完しない。
- 注文IDがなく詳細遷移できない場合は詳細リンクを表示せず、M11と履歴の再取得操作を表示する。
- 文字数の数え方、注文状況の対応表は共通仕様で統一する。

### 2.5 操作性

- 詳細リンク、「もっと見る」、再読み込み・再試行をキーボードで操作できるようにする。
- ローディング・エラー・追加取得完了を支援技術でも認識できるようにする。
- 追加取得でページ先頭に戻さず、閲覧位置を維持する。「もっと見る」が消える場合もフォーカスの移動先を確保する。

## 3. アクセス・表示制御

- 認証確認中はローディング表示とし、会員情報・注文履歴を表示しない。
- 未ログインまたは認証無効が確定した場合は、SCU-05を戻り先としてSCU-03へ遷移する。
- 認証確認の通信失敗は未ログインと区別し、M01と「再読み込み」を表示する。
- 期限切れが判別できる場合のみ、遷移先SCU-03でM07を表示する。単なる未ログインを期限切れと断定しない。
- 認証切れ・ログアウト・会員切替時は会員情報、注文履歴、継続情報、復元用データを破棄する。別の会員に以前の表示を復元しない。
- 会員情報・注文履歴は独立した領域としてローディング・成功・失敗を表示する。片方の失敗で他方の成功表示を消さない。
- APIの統合・分割によって上記の表示方針を変えない。共通の通信障害で両方取得できない場合は両領域に対応するエラーを表示する。

## 4. アクション・イベント

### 4.1 初期表示・再試行

1. 認証状態を確認し、3章に従う。
2. 会員情報と注文履歴の先頭最大20件を取得する。各領域にローディング表示を出す。
3. カート合計数量を独立して取得する。
4. 会員情報取得成功時は氏名・メールアドレスを表示する。失敗時は会員情報領域にM03と「再読み込み」を表示し、再操作では会員情報を再取得する。
5. 履歴取得成功時は一覧、またはM02を表示し、継続情報に従って「もっと見る」またはM06を表示する。
6. 履歴初回取得失敗時は履歴領域にM04と「再試行」を表示する。再試行では先頭から取得する。
7. いずれかの取得で認証無効が判明した場合は、他の表示を継続せず3章に従う。

### 4.2 もっと見る

1. 次の履歴があり、取得中でない場合のみ、保持した継続情報で追加取得する。
2. 既存一覧を残し、ボタンを非活性にして「読み込み中…」と表示する。
3. 成功時は末尾に追加する。同じ注文IDは重複表示せず、最新の取得内容で既存カードを更新する。
4. 成功後に継続情報を更新する。次があればボタンを戻し、なければボタンを非表示にしてM06を表示する。
5. 失敗時は既存一覧を残し、M05と「再試行」を表示する。成功するまで取得位置を進めず、再試行では失敗した続きから取得する。
6. 継続情報の失効など、続きから取得できないとAPIが判定した場合はM10と「先頭から再読み込み」を表示する。操作後に先頭から取得し直し、成功時に一覧と継続情報を置き換える。
7. 認証無効が判明した場合は3章に従う。

- 次の履歴の有無は取得件数から推測せず、APIの継続情報で判定する。
- 画面離脱・先頭からの再取得・会員切替前の古い応答で現在の表示を上書きしない。

### 4.3 詳細を見る・戻る

1. 対象の注文IDでSCU-09へ遷移する。
2. SCU-09から戻った場合は認証を確認し、同じ会員であることを確認した後、可能な範囲で取得済み一覧・継続情報・スクロール位置を復元する。
3. 復元できない場合は先頭から取得する。
4. 復元できた場合も、閲覧した注文の最新情報とカート数量を再取得する。更新対象は該当カードとし、一覧全体を先頭へ戻さない。
5. 対象注文の更新に失敗した場合は既存カードを残し、M09と「再試行」を表示する。既存表示を最新と断定しない。
6. APIから参照不可・対象なしが返った場合は、該当カードの詳細情報を除去し、M11と履歴の再取得操作を表示する。認証無効の場合は3章を優先する。

### 4.4 ログアウト（CMN-01連携）

- ログアウト成功時は表示・復元用データを破棄し、共通ログアウト仕様の遷移先へ移動する。
- ブラウザの戻る操作でも認証確認前に会員情報を再表示しない。
- ログアウト失敗・結果不明の扱いは共通認証仕様に従う。

## 5. 状態・メッセージ一覧

| ID | 状態 | 表示文言・操作 |
| --- | --- | --- |
| M01 | 認証確認失敗 | 「ログイン状態を確認できませんでした。再読み込みしてください。」と「再読み込み」。 |
| M02 | 履歴取得成功・0件 | 「注文履歴はありません。」 |
| M03 | 会員情報取得失敗 | 「会員情報の取得に失敗しました。再読み込みしてください。」と「再読み込み」。 |
| M04 | 履歴初回取得失敗 | 「注文履歴の取得に失敗しました。再試行してください。」と「再試行」。 |
| M05 | 履歴追加取得失敗 | 「続きの注文履歴を取得できませんでした。再試行してください。」と「再試行」。 |
| M06 | 全件表示完了・1件以上 | 「すべての注文履歴を表示しました。」 |
| M07 | 期限切れと判別できる場合 | SCU-03で「ログインの有効期限が切れました。再度ログインしてください。」 |
| M08 | 注文状況が未定義・欠損 | 「状況を確認できません」 |
| M09 | 戻った際の対象注文更新失敗 | 「注文状況を更新できませんでした。表示内容が最新でない可能性があります。」と「再試行」。 |
| M10 | 続きからの取得不可 | 「続きの注文履歴を取得できません。先頭から再読み込みしてください。」と「先頭から再読み込み」。 |
| M11 | 注文の参照不可・表示に必要な識別情報の欠損 | 「この注文の情報を表示できません。注文履歴を再読み込みしてください。」と履歴の再取得操作。 |

- 処理中のボタンラベルは「読み込み中…」とする。
- データ欠損時の補助文言は「商品情報を取得できません」「取得できません」とする。
- エラーは対象領域に表示し、再試行・状態更新に応じて不要なエラーを解除する。
- M07の引き継ぎはSCU-03・共通認証設計に従う。

## 6. 画面で必要なAPI連携項目

論理項目を列挙する。APIの統合・分割、URL・メソッド・物理名・型・結果コードはAPI設計で確定する。会員の特定には共通認証情報を用い、画面から任意の会員IDを指定する方式を前提にしない。

### 6.1 認証状態・会員情報取得

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通の認証・セッション情報 | 認証確認、対象会員の特定。 |
| 受信 | 認証状態・処理結果・エラー種別 | 表示、ログイン遷移、通信エラーの区別。期限切れを判別可能なら案内に使用する。 |
| 受信 | 氏名 | 会員情報表示。 |
| 受信 | メールアドレス | 会員情報表示。 |
| 受信・共通管理 | 同じ会員であることを判別できる情報 | 一覧復元時の別会員データ混入防止。既存の認証管理で満たせる場合は追加項目不要。 |

### 6.2 注文履歴一覧・追加取得

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通の認証情報 | 自分の注文履歴取得。 |
| 送信 | 取得件数 | 最大20件。API固定の場合は送信省略可。 |
| 送信 | 継続情報 | 初回は先頭、追加時は前回成功応答の続き。 |
| 受信 | 処理結果・エラー種別 | 成功・0件・認証無効・通信失敗・継続情報失効等の区別。 |
| 受信 | 注文履歴配列 | 注文日時降順、同一日時は注文ID降順で表示。 |
| 受信・注文ごと | 注文ID | 詳細遷移・重複防止・該当カード更新。 |
| 受信・注文ごと | 注文番号 | 利用者向け表示。注文IDと同一とする場合は共用可。 |
| 受信・注文ごと | 注文確定日時 | JST表示。タイムゾーンを判別できる形式で受け取る。 |
| 受信・注文ごと | 注文状況コード・利用者向け表示名または共通対応表 | 状況表示。未知のコードはM08。 |
| 受信・注文ごと | 注文確定時の税込総額 | 送料・手数料・割引を反映した総額表示。 |
| 受信・注文ごと | 先頭明細の注文時点の商品名 | 代表商品名表示。 |
| 受信・注文ごと | 注文時点の商品数量合計 | 「合計N点」表示。 |
| 受信 | 次の履歴の有無 | 「もっと見る」または全件表示完了の判定。 |
| 受信 | 次回取得用の継続情報 | 追加取得に使用。 |

### 6.3 詳細から戻った際の注文情報取得

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通の認証情報 | 対象注文へのアクセス確認。 |
| 送信 | 注文ID | 更新するカードの指定。 |
| 受信 | 処理結果・エラー種別 | 更新成功・失敗・参照不可・認証無効の区別。 |
| 受信 | 注文ID、最新の注文状況、カード表示に必要な注文情報 | 6.2と同じ意味の項目で対象カードを更新する。 |

- 専用APIの新設を必須とせず、SCU-09の注文詳細取得API等で満たせる場合は共用する。

| --- | --- | --- |

| 受信 | カート内合計数量 | ヘッダーバッジ更新。 |
