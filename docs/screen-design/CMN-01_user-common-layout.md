# CMN-01: ユーザー側共通レイアウト

## 1. 基本情報

- **物理名:** `user-common-layout`
- **対象:** 会員・非会員・ゲストユーザー。
- **適用画面:** SCU-01〜SCU-10。
- **目的:** 共通ナビゲーション、認証状態別メニュー、カート数量、共通通知を提供する。
- **遷移先:** SCU-01（商品一覧）、SCU-06（カート）、SCU-05（マイページ）、SCU-03（ログイン）、SCU-04（会員登録）。
- **連携:** CMN-02（フッター）。重要処理中の遷移制御は各画面・フッターとも共有する。
- **対象外:** 管理者ヘッダー（CMN-03）、ヘッダー内検索、ミニカート、他端末の一括ログアウト。
- **記載範囲:** 配置、表示、操作、通知、画面間連携、API項目。セッション・失効・キャッシュ管理の内部処理は共通認証・機能設計で扱う。
- **文言:** 要件定義にも記載し、API設計時に結果コードと照合する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 配置

- ヘッダーはページ先頭の通常配置とし、固定・スクロール追従は行わない。
- ヘッダー、補助通知領域、各画面のメインコンテンツの順に配置する。
- 768px以上は左にロゴ、右にカート・会員表示・アカウント操作を横並びで配置する。
- 768px未満はロゴ・カート・「メニュー」ボタンを常時表示し、会員表示・アカウント操作は開閉メニュー内に配置する。「常時表示」はヘッダー内で折りたたまない意味であり、画面への固定ではない。
- 先頭に「メインコンテンツへスキップ」を置き、キーボードフォーカス時に表示する。

### 2.2 要素

| 要素 | 表示・動作 |
| --- | --- |
| ロゴ・サイト名 | SCU-01の検索条件なし・先頭からの初期表示へ遷移する。 |
| カート | SCU-06へ遷移する。認証未確定でも導線自体は表示する。遷移先で認証・対象カートを確認する。 |
| バッジ | 保存済み全明細数量合計。購入不可分を含み、0は非表示、1〜99は数値、100以上は「99+」。 |
| 会員氏名 | ログイン済みで氏名取得成功時に「氏名様」と表示する。例：「山田太郎様」。氏名と様の間に空白を入れない。 |
| マイページ | ログイン済みの場合のみ表示しSCU-05へ遷移する。 |
| ログアウト | ログイン済みの場合のみ表示する。確認ダイアログなしで実行する。 |
| ログイン | 未ログイン確定時のみ表示しSCU-03へ遷移する。 |
| 新規会員登録 | 未ログイン確定時のみ表示しSCU-04へ遷移する。 |

- 氏名はHTMLとして実行しない。長い場合は表示幅で省略して「…」を付け、「様」は残す。支援技術では氏名全文を認識できるようにする。
- 氏名欠損・取得失敗時は氏名のみ省略し、認証が確認できている場合はマイページ・ログアウトを表示する。氏名取得失敗を認証失敗と同一視しない。
- 未保存の数量入力・未統合ゲストカート数量を会員バッジへ独自加算しない。

### 2.3 スマホメニュー

- 初期状態は閉じる。「メニュー」ボタンで開閉する。
- モーダルではない開閉領域として実装し、通常のTab順序で操作できるようにする。閉じた領域へフォーカスを入れない。
- ボタンに開閉状態と対象領域を関連付ける。
- Escで閉じ、メニューボタンへフォーカスを戻す。ボタンによる閉操作でもフォーカスを維持する。
- 項目から遷移したら閉じ、遷移先画面のフォーカス制御へ従う。
- PC表示へ切り替わった際は通常ナビゲーションを表示し、非表示になる要素にフォーカスを残さない。

### 2.4 補助通知

| 条件 | 表示・操作 |
| --- | --- |
| 数量取得失敗 | UH01と「カート情報を再取得」。 |
| 公開画面で認証確認失敗 | UH02と「再確認」。保護画面では画面本体の認証エラーを優先する。 |
| ログアウト失敗確定 | UH04と「再度ログアウトを実行」。 |
| ログアウト結果不明 | UH05と「ログイン状態を再確認」「再度ログアウトを実行」。 |
| ログアウト成功 | SCU-01へ遷移後、UH03を3秒表示。 |
| 公開画面で期限切れと判明 | UH06。通常の未ログインには表示しない。 |

- 同じ失敗を画面本体で通知する場合、ヘッダー側は重複表示しない。SCU-06のC02・C18等の表示状態を共有する。
- バッジの数量未確認状態は、通知を省略した場合も維持する。
- 通知は通常の公開コンテンツ表示を妨げない。ただし認証不明・ログアウト中の会員情報非表示等は優先する。

### 2.5 操作性

- リンク、開閉、ログアウト、再取得をキーボードで操作できるようにする。
- カートリンクの名前は「カート（3点）」「カート（空）」「カート（数量未確認）」とする。100以上も取得済み実数量を読み上げる。
- 数量更新・エラー・処理状態を支援技術でも通知する。
- 非活性のリンクは見た目だけでなく遷移も抑止する。

## 3. 状態制御

### 3.1 認証

| 状態 | メニュー |
| --- | --- |
| 初回確認中 | アカウント領域はプレースホルダー。氏名・ログイン・マイページ等を推測表示しない。 |
| ログイン済み | 氏名様（取得時）、マイページ、ログアウト。 |
| 未ログイン確定 | ログイン、新規会員登録。 |
| 確認通信失敗 | 会員氏名を隠し、通常のアカウント操作を表示しない。再確認を提供する。 |
| ログアウト処理中 | 「ログアウト中…」。通常のヘッダー遷移と会員操作を止める。 |
| ログアウト失敗・結果未確定 | 会員の個人情報を非表示にし、復旧操作を表示する。未確認のまま通常の会員操作を再開しない。 |

### 3.2 カート数量

| 状態 | 表示 |
| --- | --- |
| 初回取得中・認証未確定 | バッジ非表示、数量未確認。 |
| 取得成功・0 | バッジ非表示、空。 |
| 取得成功・1〜99 | 数量表示。 |
| 取得成功・100以上 | 99+。 |
| 初回取得失敗・再取得失敗 | バッジ非表示、数量未確認。古い数量を最新として残さない。 |

- 成功時はUH01を解除する。
- カート識別・会員識別・取得更新の順序を確認して応答を反映する。ログアウト前・別会員・以前のゲストカートの応答を無視する。
- 再確認中に既存の値を使う場合も、同じ認証状態・対象カートで有効な共通キャッシュに限る。認証切替時は即座に無効化する。

### 3.3 処理中の操作

- ログイン、登録・メール確認、カート更新・削除・統合、注文確定等の通信中は、画面側の処理状態に従いヘッダーの遷移・ログアウトを一時抑止する。
- CMN-02と各画面の離脱導線にも同じ抑止状態を共有する。スキップリンク・本文の閲覧まで止める必要はない。
- 結果不明になった後は、各画面の「結果の再確認」「注文履歴を確認する」等を利用可能にする。通信中の全操作抑止を無期限に継続しない。
- ブラウザの戻る・再読み込み・タブ終了まで確実に防げる前提にせず、再訪問時の結果確認を各機能と連携する。
- 認証確認等の通常の読み取り処理だけを理由に、公開画面の全ナビゲーションを停止しない。

## 4. アクション・イベント

### 4.1 初期表示・画面遷移・復帰

1. 共通管理に有効な認証状態があれば利用し、確認が必要なら認証APIを呼ぶ。
2. 会員・ゲストと対象カートを特定してから数量を取得する。認証未確定時にゲストの値を先行表示しない。
3. 公開画面の商品情報取得等は並行してよい。保護画面の本文は各画面の認証制御を優先する。
4. 各画面と共通ヘッダーの同一取得は共用し、重複要求をまとめる。
5. カート追加・更新・削除・統合・注文成立等の応答に最新数量があれば、その値で同期できる。追加の数量APIを必須としない。
6. タブ復帰・戻る操作で認証と数量を再確認する。SCU-06が編集中・更新中なら背景のカート再取得を保留し、画面側の同期完了後に反映する。
7. 会員切替・認証無効時は会員表示・数量・会員に紐付く復元用データを無効化する。

### 4.2 認証無効の通知

- SCU-05・07・08・09は各画面の戻り先ルールでSCU-03へ案内する。
- 会員カート利用中のSCU-06は、SCU-06を戻り先として再ログインへ案内する。ゲストの空カートへ黙って切り替えない。
- SCU-01・02・10は公開本文を継続し、未ログインメニューへ切り替える。期限切れと判別できる場合はUH06。
- SCU-03・04は認証・登録処理の状態に従う。カート統合の再試行中等の認証切れも共通認証仕様と連携する。
- ゲスト表示へ切り替える場合も会員カートを転記・合算しない。

### 4.3 再確認・数量再取得

- 対象ボタンを非活性にし「確認中…」と表示する。
- 認証を再確認する場合は、結果に応じて対象カートも確認する。
- 数量再取得は現在の利用者に対応するカートで実行する。
- 成功時は該当通知を解除し、失敗時は通知と再試行操作を残す。認証不明のまま別対象の数量を取得しない。

### 4.4 ナビゲーション

- ロゴはSCU-01の検索条件なし・先頭表示へ移動する。同画面の場合も検索条件をクリアする。
- カートはSCU-06、マイページはSCU-05へ移動する。
- ログイン・新規登録では、現在の有効なアプリ内画面を戻り先としてSCU-03・SCU-04へ引き継ぐ。商品詳細は対象商品IDも含める。
- SCU-03・04間は元の戻り先を維持する。両画面自身を戻り先にして循環させない。
- SCU-10・戻り先不明・不正の場合はSCU-01とする。外部URLは受け付けない。

### 4.5 ログアウト

1. 重要処理の通信中でない場合に、確認ダイアログなしで開始する。
2. 「ログアウト中…」と表示し、通常の会員操作・ヘッダー遷移を止める。
3. 現在のブラウザで利用しているログイン状態の終了を要求する。他端末を一括ログアウトする操作は行わない。
4. 成功時は認証・会員情報・履歴・配送先入力・会員カート表示・復元キャッシュ等を破棄する。DBの会員カートや未解決注文の記録は削除しない。
5. 以前のゲストカート識別情報も端末から解除する。ただし未統合データ等のサーバー側記録を、ログアウトだけで削除しない。
6. 新しいゲストカートは必要になった時点で作成する。会員数量をバッジに残さず、ゲスト数量を確認できるまでは未確認表示とする。
7. 履歴置換でSCU-01へ遷移し、UH03を3秒表示する。戻る操作でも認証確認前に会員情報を再表示しない。
8. 同じブラウザでセッションを共有する別タブは、次回の認証確認・APIアクセス時にログアウトを反映する。

### 4.6 ログアウト失敗・結果不明

- 個人情報・会員専用表示を隠して認証状態を確認する。
- セッション無効化が確認できた場合は成功時と同様にSCU-01へ遷移する。
- 失敗が確定した場合はUH04、成否不明の場合はUH05と復旧操作を表示する。
- 「ログイン状態を再確認」は確認のみを行い、「再度ログアウトを実行」は同じブラウザのログアウトを再要求する。復旧通信中のみ両操作を非活性にする。
- 未確認のままログアウト成功と通知しない。ログイン中と再確認できた場合でも、失敗通知とログアウト再試行を優先して表示する。
- 公開本文は表示できるが、会員の個人情報を復旧通知と同時に自動再表示しない。

## 5. 状態・メッセージ一覧

| ID | 状態 | 文言 |
| --- | --- | --- |
| UH01 | 数量取得失敗 | カート情報の取得に失敗しました。 |
| UH02 | 認証確認失敗 | ログイン状態を確認できませんでした。 |
| UH03 | ログアウト成功 | ログアウトしました。 |
| UH04 | ログアウト失敗確定 | ログアウト処理に失敗しました。もう一度お試しください。 |
| UH05 | ログアウト結果不明 | ログアウトが完了したか確認できませんでした。ログイン状態を再確認するか、もう一度ログアウトをお試しください。 |
| UH06 | 公開画面での認証期限切れ | ログインの有効期限が切れました。会員機能をご利用になる場合は再度ログインしてください。 |

- 操作ラベル：「カート情報を再取得」「再確認」「ログイン状態を再確認」「再度ログアウトを実行」。
- 処理中：「確認中…」「ログアウト中…」。
- UH03は3秒の通知。それ以外は解消・対応操作・遷移に応じて表示を更新する。表示を消しても未解決状態自体を成功へ変更しない。

## 6. 画面で必要なAPI連携項目

論理項目を列挙する。URL・メソッド・物理名・型・結果コードはAPI設計で定義する。各画面との重複取得は共通管理で省略できること。

### 6.1 認証状態・会員表示

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証・セッション情報 | 現在のブラウザの認証確認。 |
| 受信 | 認証状態・処理結果・エラー種別 | ログイン、未ログイン、確認失敗を区別。期限切れは判別できる場合に通知。 |
| 受信・ログイン時 | 会員識別情報 | 会員切替・別会員の応答・キャッシュ混入防止。 |
| 受信・ログイン時 | 表示用氏名・取得状態 | 「氏名様」。取得不可なら氏名のみ省略する。 |

### 6.2 カート数量

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員認証情報またはゲストカート識別情報 | 対象カート特定。 |
| 受信 | 保存済み全明細数量合計 | バッジ・実数量の読み上げ。 |
| 受信 | 処理結果・エラー種別 | 0件と数量不明の区別。 |
| 受信・必要時 | カート識別・更新状態の識別情報 | 対象一致・更新順序確認。要求時の共通状態でも補完し、具体方式はAPI設計で定義。 |

### 6.3 ログアウト

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 現在のブラウザの認証・セッション情報 | 当該ログイン状態の終了。 |
| 受信 | 処理結果・エラー種別 | 成功・失敗の表示。通信断等は画面側で結果不明として扱い、6.1で確認する。 |

### 6.4 画面間の共通連携（業務APIの新設は不要）

| 情報 | 用途 |
| --- | --- |
| 最新数量・対象カート・会員の識別、応答順序 | 各画面の更新応答からバッジを同期する。 |
| 重要処理中・結果不明・許可する復旧操作 | ヘッダー・フッター・画面本体で一貫した遷移制御。 |
| 数量編集中・再同期保留 | SCU-06の入力と共通取得の競合防止。 |
| 本文で表示中の共通エラー | 補助通知の重複防止。 |
| 有効な戻り先 | SCU-03・04への引き継ぎ。 |
