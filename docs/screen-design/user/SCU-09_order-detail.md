# SCU-09: 注文詳細画面

## 1. 基本情報

- **物理名:** `order-detail`
- **対象:** ログイン済みユーザー。
- **目的:** 本人の成立済み注文（成立後のキャンセル済みを含む）について、現在の注文状況と、注文時点の商品・金額・配送先・モック決済記録を確認する。
- **遷移先:** SCU-05（マイページ）、SCU-02（商品詳細）、SCU-01（商品一覧）、SCU-03（ログイン）。共通ヘッダーのカート導線はSCU-06へ遷移する。
- **共通画面:** CMN-01、CMN-02。
- **対象外:** ユーザーによるキャンセル・注文変更・配送先変更、領収書発行、再注文操作、部分キャンセル・一部返金。
- **記載範囲:** 画面構成、表示、状態別制御、遷移、文言、API連携項目。注文状態遷移、キャンセル実行、モック返金・取消、在庫処理の内部仕様は管理者側・機能設計で定義する。
- **文言:** 要件定義にも記載し、API設計時に結果コード・表示条件と照合する。文言IDはAPIコードではない。

## 2. 画面構成

### 2.1 共通レイアウト・導線

- 上部にCMN-01、末尾にCMN-02、タイトルに「注文詳細」を表示する。
- 上部に「注文履歴へ戻る」を表示しSCU-05へ遷移する。SCU-08から来た場合もSCU-05への導線とする。
- 「商品一覧へ」からSCU-01へ遷移する。
- バッジはカート全明細の保存済み数量合計。0は非表示、100以上は「99+」。取得失敗は数量不明とし、注文詳細の閲覧を妨げない。
- 本人の注文情報取得後はD01を表示し、キャンセル済みならD02も表示する。
- 注文基本情報・明細の後に、支払い情報と配送先情報を配置する。768px以上では後者2領域を左右2カラム、768px未満では縦1列とする。

### 2.2 注文基本情報

| 項目 | 表示仕様 |
| --- | --- |
| 注文ID | 識別情報として保持する。画面には利用者向け注文番号を表示する。 |
| 注文番号 | APIの注文番号。欠損時は「取得できません」。 |
| 注文確定日時 | 注文時点の確定日時をJSTの「YYYY/MM/DD HH:mm」に整形。欠損・不正時は「取得できません」。 |
| 注文状況 | 現在の状態を共通対応表の利用者向け表示名で表示する。色だけで区別しない。未定義・欠損時はD08。 |
| キャンセル日時 | キャンセル済みの場合のみ表示する。JSTに整形し、欠損・不正時は「取得できません」。 |
| キャンセル理由 | キャンセル済みの場合のみ利用者向け理由をテキスト表示する。理由未登録が確認できた場合は「理由の登録はありません」。取得不正・不明は「取得できません」。 |

- 管理者の内部メモ等、利用者への開示対象でない理由は表示しない。

### 2.3 注文商品明細

- 注文明細番号の昇順で表示する。
- 商品画像と詳細リンクの可否は現在の商品情報を使用し、商品名・単価・数量・小計は注文時点の記録を使用する。
- 見出し付近にD11を表示し、画像が注文時点と異なる可能性を案内する。

| 項目 | 表示仕様 |
| --- | --- |
| 商品ID | 現在の商品詳細への遷移指定に使用する。非表示。 |
| 商品画像 | 現在登録されている画像を使用する。APIが参照可能なURLを返した場合のみ表示する。代替テキストは注文時の商品名等を使用する。 |
| 代替画像 | 商品削除等で参照可能な画像がない、URL未設定、取得失敗の場合はNo Image。切り替えを繰り返さない。 |
| 商品名 | 注文時点の商品名を全文表示する。現在の名称へ置き換えない。欠損時は「商品情報を取得できません」。 |
| 商品リンク | APIが現在の詳細遷移を許可した場合のみSCU-02へリンクする。それ以外はテキスト表示としD06を添える。 |
| 注文時税込単価 | 注文時点の税込単価を円単位・小数なし・3桁区切りで表示。例：「￥1,980（税込）」。 |
| 数量 | 注文時点の数量を「数量：N点」と表示する。 |
| 税込明細小計 | 注文時点の税込小計を表示し、画面で単価×数量を再計算しない。 |

- 商品画像の注文時点の複製・履歴保持は行わない。
- 画像参照可否と商品詳細遷移可否は別々に扱い、画面側で公開・非公開を推測しない。
- 成立済み注文で明細が0件の場合はD10と再読み込みを表示する。「商品なしの正常な注文」として表示しない。確認できた基本情報等は表示を継続できる。

### 2.4 金額内訳・支払い情報

| 項目 | 表示仕様 |
| --- | --- |
| 商品合計（N点） | 注文時点の明細数量合計。商品種類数ではない。 |
| 税込商品合計 | 注文確定時の値を表示する。 |
| 送料（税込） | 注文確定時の値を表示する。現行の送料設定から再計算しない。 |
| 決済手数料 | 注文確定時の値を表示する。0円も省略せず「￥0」と表示する。 |
| 合計請求金額（税込） | 注文確定時の総額。キャンセル・モック返金後も保持して表示する。 |
| 支払い方法 | 注文時点の「クレジットカード（モック）」等の表示名。 |
| テストカード | 注文時点の架空カード表示名・模擬下4桁。保存解除・上書き後も当該注文の記録を表示する。 |
| モック決済状態 | 現在の状態を利用者向け表示名で表示する。未定義・欠損時はD12。 |
| モック返金・取消状態 | キャンセル等に関連する処理がある場合、APIが返す状態を表示する。キャンセル済みだけを根拠に完了扱いにしない。 |
| モック返金・取消額 | APIが返す対象額を注文総額とは別欄に表示する。全額のみを対象とするが、画面で総額をコピーして補完しない。 |

- 返金・取消処理の「対象外」が確認できた場合は共通表示名で明示する。状態不明はD12。対象額が必要だが欠損する場合は「取得できません」とする。
- 取消・返金の処理中、完了、失敗等を共通対応表で区別する。実際の返金があるような表示をしない。
- 実カード番号・セキュリティコードは取り扱わない。

### 2.5 配送先・注文者情報

- 固定表示項目として以下を表示する。現在の会員情報や保存配送先で補完しない。

| 項目 | 表示仕様 |
| --- | --- |
| 受取人氏名 | 注文時点の記録。 |
| 郵便番号 | 注文時点の7桁を「〒123-4567」に整形。欠損・不正時は「取得できません」。 |
| 住所 | 注文時点の都道府県・市区町村・番地・建物名・部屋番号。建物名等が未入力と確認できる場合はその部分を省略する。 |
| 電話番号 | 注文時点の数字列を表示し、先頭の0を保持する。 |
| 注文者氏名 | 注文時点の記録を表示する。 |
| 注文者メールアドレス | 注文時点の記録を表示する。 |

- 配送先・注文者情報は参照のみ。編集フォームを設けない。
- 部分的な項目欠損は「取得できません」とし、取得できた他の領域は表示する。欠損と任意項目の未入力を区別する。

### 2.6 操作性

- 全リンク・再読み込みをキーボードで操作できるようにする。
- ローディング・エラー・状態更新は支援技術でも認識できるようにする。
- 商品名・氏名・住所・キャンセル理由等はテキスト表示し、HTMLを実行しない。

## 3. アクセス・表示制御

| 条件 | 表示・遷移 |
| --- | --- |
| 認証確認中 | ローディング。個人情報・注文詳細を表示しない。 |
| 未ログイン・認証無効確定 | 表示を破棄し、対象注文IDを含むSCU-09を戻り先としてSCU-03へ遷移する。期限切れと判別できる場合のみD07を引き継ぐ。 |
| 認証確認通信失敗 | 詳細を非表示にしてD03と再読み込み。未ログインと断定しない。 |
| 本人の成立済み注文（成立後のキャンセルを含む） | 詳細を表示する。 |
| ID未指定・不正・不存在・他会員・未成立 | SCU-09内に共通のD04とSCU-05・SCU-01への導線を表示する。SCU-10へ遷移しない。 |
| 初回の注文詳細取得失敗 | D05と再読み込み・SCU-05への導線。 |
| 同じ会員・同じ注文の再取得失敗 | 認証が確認できている場合のみ既存表示を残し、D09と再読み込みを表示する。古い値を最新と断定しない。 |

- 成立前の注文処理・結果不明はSCU-07で扱い、本画面の履歴対象に含めない。参照不可を「注文失敗確定」と説明しない。
- 所有権・成立状態をバックエンドで検証する。URLの注文IDだけで許可しない。
- 他会員の注文の存在・内容を開示しない。
- 認証切れ・ログアウト・会員切替時は表示・復元用データを破棄する。

## 4. アクション・イベント

### 4.1 初期表示・再読み込み

1. 認証状態と対象注文IDを確認し、3章に従う。
2. 注文詳細を取得し、初回はローディング表示を出す。
3. カート数量は独立して取得する。失敗だけで詳細表示を止めない。
4. 本人の成立済み注文として取得できたら各領域を表示する。キャンセル済みならD02と取消・返金情報を表示する。
5. 部分欠損は対象項目のみ代替表示する。本人の成立済み注文であること自体を確認できなければ詳細を表示しない。
6. 通信エラー・認証無効・参照不可を区別する。参照不可になった場合は以前の詳細も除去する。
7. 別注文・別会員への切り替え前や画面離脱前の古い応答を反映しない。

### 4.2 商品詳細への遷移・復帰

- APIが詳細遷移可とした商品のみ、商品IDでSCU-02へ遷移する。
- SCU-02では現在の商品情報が表示されるため、注文記録の金額・名称と異なる場合がある。
- 商品画面から戻った場合、認証確認後に注文詳細とカート数量を再取得する。注文時点の記録はそのまま、現在の状況・画像・リンク可否を更新する。
- タブ復帰時も同様に再取得する。初期実装では定期ポーリングは行わない。
- 再取得でフォーカス・スクロール位置を不必要に先頭へ戻さない。失敗は3章のD09等に従う。

### 4.3 注文履歴へ戻る

- SCU-05へ遷移する。
- SCU-05から来た場合は、同じ会員の一覧・継続情報・スクロール位置の復元と、閲覧した注文カードの最新化に必要な注文IDを引き継ぐ。
- 復元不可、SCU-08からの遷移、直接アクセスの場合はSCU-05の初期表示とする。

### 4.4 ログアウト

- ログアウト成功時は注文詳細と個人情報を破棄し、共通仕様の遷移先へ移動する。
- ブラウザの戻る操作でも認証確認前に注文情報を再表示しない。
- 本画面の表示・再取得で、注文・取消・返金・カート更新を実行しない。

## 5. 状態・メッセージ一覧

| ID | 状態 | 文言 |
| --- | --- | --- |
| D01 | テスト注文 | ※これはテスト注文の記録です。実際の決済・請求および商品の発送は行われません。 |
| D02 | キャンセル済み | この注文はキャンセルされています。テスト注文のため、実際の請求および返金処理は発生しません。 |
| D03 | 認証確認失敗 | ログイン状態を確認できませんでした。再読み込みしてください。 |
| D04 | 参照不可・不存在・ID不正等 | 指定された注文情報を表示できません。マイページの注文履歴からご確認ください。 |
| D05 | 初回詳細取得失敗 | 注文詳細の取得に失敗しました。再読み込みしてください。 |
| D06 | 商品詳細遷移不可 | 現在この商品の詳細ページは表示できません。 |
| D07 | 認証期限切れ | ログインの有効期限が切れました。再度ログインしてください。 |
| D08 | 注文状況未定義・欠損 | 状況を確認できません |
| D09 | 詳細再取得失敗 | 最新の状態を取得できませんでした。表示内容が最新でない可能性があります。再読み込みしてください。 |
| D10 | 明細0件・取得不正 | 注文明細を表示できません。再読み込みしてください。 |
| D11 | 現在画像の案内 | 商品画像は現在登録されているものです。注文時点の画像と異なる場合があります。 |
| D12 | モック決済・返金状態不明 | テスト決済・返金の状態を確認できません。 |

- 処理中：「読み込み中…」。
- 欠損時：「商品情報を取得できません」「取得できません」。
- キャンセル理由未登録：「理由の登録はありません」。
- D07はSCU-03へ引き継ぐ。D04ではSCU-05・SCU-01への導線、D03・D05・D09・D10では再読み込みを提供する。
- 注文状況、モック決済・返金・取消の表示名は共通状態定義で確定し、API設計時に文言と対応を確認する。

## 6. 画面で必要なAPI連携項目

以下は論理項目。URL・メソッド・物理名・型・結果コードはAPI設計で定義する。SCU-05のカード更新・SCU-08の完了表示と共用できるが、不要な住所・電話番号まで各画面で取得することを必須としない。SCU-08の保存結果は別取得でもよい。

### 6.1 認証・注文詳細取得

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証・セッション情報 | 本人の認証・所有権確認。 |
| 送信 | 注文ID | 対象注文の指定。 |
| 受信 | 認証状態・処理結果・エラー種別 | 詳細、ログイン遷移、参照不可、通信失敗を区別。 |
| 受信 | 注文ID・注文番号・成立確認情報 | 対象識別、番号表示、表示対象の確認。 |
| 受信 | 注文確定日時 | JST表示。タイムゾーンを判別できる形式。 |
| 受信 | 現在の注文状況コード・利用者向け表示名または共通対応表 | 状況・キャンセル表示。 |
| 受信 | キャンセル日時・利用者向け理由・理由登録有無 | キャンセル情報表示。内部メモは返さない。 |
| 受信 | 注文明細配列 | 明細番号昇順。 |
| 受信・明細ごと | 注文明細ID・明細番号 | 識別・固定順序。 |
| 受信・明細ごと | 商品ID・現在の商品詳細遷移可否 | SCU-02へのリンク制御。 |
| 受信・明細ごと | 現在参照可能な商品画像URL | 現在画像表示。取得不可はNo Image。 |
| 受信・明細ごと | 注文時点の商品名・税込単価・数量・税込小計 | 注文記録表示。現在の商品マスタで置き換えない。 |
| 受信 | 注文時点の数量合計・税込商品合計・税込送料・税込手数料・税込総額 | 金額内訳・点数表示。 |
| 受信 | 注文時点の支払い方法・架空カード表示名・模擬下4桁 | 注文時のモック支払い情報。 |
| 受信 | 現在のモック決済状態・取消／返金対象有無・処理状態・利用者向け表示名・対象額 | 注文状態と独立したモック処理の表示。 |
| 受信 | 注文時点の受取人氏名・郵便番号・都道府県・市区町村番地・建物名部屋番号・電話番号 | 配送先の固定表示。 |
| 受信 | 注文時点の注文者氏名・メールアドレス | 注文者情報の固定表示。 |

- 任意項目の未登録・対象外と、必須項目の欠損・取得不正を区別できる応答とする。
- 商品画像の注文時URL・画像履歴は表示要件に含めない。商品削除・非公開時の画像提供可否はAPI側で判断する。

### 6.2 カート数量取得（共通）

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員認証情報 | 会員カート特定。 |
| 受信 | 保存済み全明細数量合計・処理結果・エラー種別 | バッジ更新、0件と取得失敗の区別。 |
