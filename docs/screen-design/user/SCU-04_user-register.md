# SCU-04: 新規会員登録画面

## 1. 基本情報

- **物理名:** `user-register`
- **対象:** 未ログイン・ゲストユーザー。
- **目的:** 氏名・メールアドレス・パスワードを登録し、メール確認を完了する。完了後はログイン画面へ案内する。
- **主な遷移先:** ユーザーログイン画面（SCU-03）、商品一覧画面（SCU-01）、カート画面（SCU-06）。
- **共通画面:** CMN-01（ユーザー側共通レイアウト）、CMN-02（ユーザー側共通フッター）。
- **画面内ステップ:** 登録情報入力 → メール確認コード入力。同じSCU-04内で切り替える。
- **記載範囲:** 表示・入力制御、操作、状態別メッセージ、API連携項目。認証・会員データ管理・試行制限・カート統合の内部処理は共通仕様・機能設計で定義する。
- **文言の扱い:** 本書の文言を要件定義にも記載する。API設計時に結果コード・対象項目・表示条件との対応を再確認し、両資料を同期する。APIから表示文言そのものを返す方式を必須とはしない。

## 2. 画面構成

### 2.1 共通エリア

- 画面上部にCMN-01、メインコンテンツの後にCMN-02を表示する。
- カートアイコンはSCU-06へ遷移する。
- カートバッジは全商品の数量合計を表示する。0は非表示、100以上は「99+」とする。
- カート情報取得失敗時は数量不明として扱い、0件と断定しない。登録・メール確認操作は継続できる。
- メインコンテンツは画面中央に配置し、狭い画面では左右に余白を確保して1列で表示する。

### 2.2 登録情報入力ステップ

- タイトルは「新規会員登録」とする。
- 登録後に確認メールが届き、メール確認後にログインが必要になることを案内する。

| 要素 | 表示・動作仕様 |
| --- | --- |
| 氏名 | ラベル付きテキスト入力欄。前後の空白を検証・送信前に除去する。 |
| メールアドレス | ラベル付きメールアドレス入力欄。ログインIDとして使用する旨を表示し、前後の空白を除去する。 |
| パスワード | 初期状態は伏字。入力条件を常時表示する。入力文字を勝手に変更しない。 |
| パスワード（確認用） | 初期状態は伏字。入力内容の一致確認に使用し、APIへ送信しない。 |
| パスワード表示切替 | 各欄に独立して配置し、対象欄の伏字／平文を切り替える。 |
| 登録する | 入力検証後に登録処理を開始する。 |
| ログイン画面へのリンク | 「すでにアカウントをお持ちの方はこちら」。SCU-03へ戻り先情報を引き継ぐ。 |
| エラー領域 | 項目エラーは入力欄付近、全体エラーはフォーム上部に表示する。 |

### 2.3 メール確認ステップ

- タイトルは「メールアドレスの確認」とする。
- 送信先はAPIが返すマスク済みのメールアドレスを表示する。マスク済み情報がない場合は送信先を推測表示しない。
- 登録受付と会員登録完了を区別し、この段階ではログイン状態にしない。

| 要素 | 表示・動作仕様 |
| --- | --- |
| 案内文 | 確認コードの送信結果に応じて5章の文言を表示する。送信未確認時に送信済みと表示しない。 |
| 確認コード | ラベル付きテキスト入力欄。先頭の0を保持し、貼り付け・ワンタイムコードの自動入力を利用できるようにする。 |
| 確認する | コードの検証・確認処理を開始する。 |
| コードを再送する | 現在の確認対象にコードを再送する。再送可能になるまでは非活性とし、待機が必要な旨を表示する。 |
| ログイン画面へ戻る | SCU-03へ遷移する。元の戻り先情報を引き継ぐ。 |
| エラー領域 | コードエラーは入力欄付近、通信・試行制限等はフォーム上部に表示する。 |

- 確認コードの形式・桁数、再送間隔、待機時間の取得方法はAPI設計で確定する。画面とAPIで条件を一致させる。
- メールアドレスの編集によって既存の確認対象が変更されたように見せない。メールアドレス変更・登録やり直しの取り扱いは機能設計で定義する。

### 2.4 操作性

- 各入力欄とラベルを関連付ける。パスワード切替には「パスワードを表示」「パスワードを隠す」等の名前を付ける。
- 入力・切替・送信・リンクはキーボードで操作できる。日本語変換確定中のEnterでは送信しない。
- パスワードの貼り付け・パスワードマネージャーによる入力を妨げない。
- エラーは色だけで区別せずテキストで表示し、最初のエラー項目へフォーカスを移す。
- ステップ切替時は見出し等にフォーカスを移し、完了・エラー・再送通知を支援技術で認識できるようにする。

## 3. 表示・入力制御

### 3.1 アクセス・戻り先

- 認証状態の確認中はローディング表示とし、登録・確認APIを呼び出さない。
- ログイン済みの場合は登録フォームを表示せず、有効な戻り先へ遷移する。不明・不正な場合はSCU-01へ遷移する。
- 認証状態の確認失敗は未ログインと区別し、エラーと再試行操作を表示する。
- 未ログインの場合は登録情報入力を表示する。ただし、有効なメール確認手続きの再開情報がある場合はコード入力を表示する。
- 戻り先はアプリ内で許可された画面のみを有効とする。登録・メール確認・SCU-03への遷移を通じて保持する。
- メール確認完了後は、戻り先へ直接遷移せずSCU-03へ移動する。実際の戻り先への遷移はログイン成功後に行う。

### 3.2 入力条件

| 項目 | 条件 | エラー文言ID |
| --- | --- | --- |
| 氏名 | 必須。前後の空白除去後に1〜50文字。 | R01・R02 |
| メールアドレス | 必須。前後の空白除去後に1〜254文字、メールアドレス形式。 | R03・R04 |
| パスワード | 必須。16〜30文字の半角英大文字・英小文字・数字・記号。英大文字・英小文字・数字を各1文字以上含む。記号は任意、空白不可。 | R05・R06 |
| パスワード（確認用） | 必須。パスワードと完全一致。 | R07・R08 |
| 確認コード | 必須。API設計で定めた形式・桁数を満たすこと。数値に変換しない。 | R09・R10 |

- 不正な入力がある場合はAPIを呼び出さない。
- パスワードは空白の除去、全角半角変換、切り詰めを行わない。空白を含む場合は入力エラーとする。
- 使用可能な記号の具体的な範囲と文字数の数え方は共通入力仕様で定義し、API設計時に照合する。
- メールアドレスの大文字・小文字の扱いと一意判定は共通仕様に従い、最終結果はAPIの応答を使用する。

## 4. アクション・イベント

### 4.1 初期表示・再開

1. 認証状態と戻り先を確認し、3.1の表示・遷移を行う。
2. 登録フォームを初期表示する場合は入力欄を空にする。
3. SCU-03でメール未確認と判定されて遷移してきた場合は、有効な確認対象情報を用いてメール確認を再開する。自動再送は行わず、必要に応じて再送ボタンを使用する。
4. 再読み込み・再訪問で確認手続きを復元できる場合はコード入力を表示する。復元できない場合はR21とSCU-03への導線を表示する。
5. カート合計数量を独立して取得し、バッジに反映する。取得失敗は登録操作を妨げない。

### 4.2 登録する／登録フォームでEnter

1. 全項目を検証する。エラーがあれば項目付近に表示する。
2. 入力欄・表示切替・登録ボタンを非活性にし、「登録処理中…」と表示する。
3. 氏名・メールアドレス・パスワードを送信する。確認用パスワードは送信しない。
4. 登録受付成功時はパスワードと確認用を消去し、メール確認ステップへ切り替える。送信先・送信結果を反映する。
5. 確認済みであることがAPIの信頼できる応答から判明した場合は、確認完了時と同様にSCU-03へ案内する。
6. 登録を進められない場合はR11をメールアドレス欄付近に表示する。APIが開示しない登録状態を画面で推測表示しない。
7. その他の確定した失敗は項目別またはフォーム上部に表示する。氏名・メールアドレスは保持し、パスワード2欄は空欄・伏字へ戻し、操作を再開可能にする。
8. 結果不明の場合はR13を表示し、自動再送せずSCU-03へ案内する。パスワード2欄は消去する。

- 登録受付済みでメール送信だけ失敗したことが判明した場合は、登録処理を最初から繰り返さず、確認ステップにR17と再送操作を表示する。
- 登録受付・メール確認のどちらでも自動ログインやゲストカート統合は行わない。

### 4.3 確認する／確認フォームでEnter

1. コードを検証し、確認対象の識別情報とコードを送信する。
2. 処理中はコード入力・確認・再送を非活性にし、「確認中…」を表示する。
3. 確認完了時はコードを消去し、戻り先情報を引き継いでSCU-03へ移動する。遷移後にR20を表示する。
4. コード誤り・期限切れ・試行制限は対応する文言を表示し、入力修正または再送を案内する。制限中は該当操作を非活性にする。
5. 通信失敗で結果が不明な場合はR19とSCU-03への導線を表示する。成功・コード誤りと断定せず、自動再送しない。
6. 既に確認済みであることが信頼できる応答から判明した場合はSCU-03へ案内する。公開されたメールアドレスだけで状態照会できることは前提にしない。

### 4.4 コードを再送する

1. 再送可能な場合に、現在の確認対象の識別情報を送信する。
2. 再送中は再送ボタンと確認操作を非活性にし、「再送中…」を表示する。
3. 成功時はR16を表示し、古い入力コードを消去する。返却された送信先・待機情報を更新する。
4. 確定した送信失敗はR17、試行制限はR18を表示する。
5. 通信失敗で送信結果が不明な場合はR22を表示し、自動再送しない。
6. 待機が必要な場合は、その間の再送を受け付けない。具体的な再送間隔はAPI設計で確定する。

- 画面離脱後や別の確認対象に切り替わった後に、古い応答で現在の表示を上書きしない。

## 5. 状態・メッセージ一覧

| R07 | 確認用未入力 | 確認用パスワードを入力してください。 |

| R20 | メール確認完了 | 会員登録が完了しました。ログインしてください。 |
| R21 | 確認手続き復元不可 | 確認手続きを再開できませんでした。ログイン画面からお試しください。 |

- 処理中のラベルは「登録処理中…」「確認中…」「再送中…」とする。
- エラーはトーストだけにせずフォーム内に表示し、修正・再操作時に不要なエラーを解除する。
- R20はSCU-03への遷移後も表示できるよう引き継ぐ。登録完了通知のためにログイン済みとして扱わない。
- カート取得失敗時の通知・再取得操作はCMN-01の共通仕様に従う。

## 6. 画面で必要なAPI連携項目

以下は論理項目。URL・メソッド・物理名・型・エラーコード・確認対象の安全な識別方法はAPI設計で確定する。戻り先保持がAPIを必要とするかは共通遷移設計で定義する。

### 6.1 認証状態確認（共通）

| 方向 | 項目 | 画面での用途 |
| --- | --- | --- |
| 送信・付随 | 共通のセッション識別情報 | 現在の認証状態の確認。 |
| 受信 | ログイン済み／未ログイン、処理結果 | 登録画面表示・遷移・確認エラーの切り替え。 |

### 6.2 カート合計数量取得（共通）

| 方向 | 項目 | 画面での用途 |
| --- | --- | --- |
| 送信・付随 | ゲストカートの識別情報 | 表示対象カートの特定。 |
| 受信 | カート内合計数量 | ヘッダーバッジ更新。 |
| 受信 | 処理結果・エラー種別 | 0件と取得失敗の区別。 |

### 6.3 新規会員登録

| 方向 | 項目 | 画面での用途 |
