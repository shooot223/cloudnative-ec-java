# SCU-10: ページ未検出画面

## 1. 基本情報

- **物理名:** `user-not-found`
- **対象:** 会員・非会員・ゲストユーザー。認証不要。
- **目的:** ユーザー側の未定義URL、またはSCU-02で対象商品を表示できないことが確定した場合に案内を表示し、有効な画面へ誘導する。
- **主な遷移先:** SCU-01（商品一覧）。
- **共通ヘッダー経由の遷移先:** SCU-06（カート）、SCU-05（マイページ）、SCU-03（ログイン）。表示条件はCMN-01に従う。
- **共通画面:** CMN-01（ユーザー側共通レイアウト）、CMN-02（ユーザー側共通フッター）。
- **対象外:** 管理者側の未定義URL（SCA-06）、注文画面の参照不可案内（SCU-08・SCU-09）、通信障害・サーバーエラー、認証が必要な画面の未ログイン制御。
- **記載範囲:** 画面構成、適用条件、表示・遷移、SCU-02での共通表示、文言、API連携項目。ルーティング・HTTPレスポンス・配信基盤の設定はインフラ・機能設計で定義する。
- **文言:** 要件定義にも記載する。API設計・他画面設計時に表示条件と照合する。文言IDはAPIエラーコードではない。

## 2. 画面構成

### 2.1 共通エリア

- 上部にCMN-01、末尾にCMN-02を表示する。
- メインコンテンツは中央に配置し、狭い画面では左右余白を確保して縦1列とする。
- カートアイコンはSCU-06へ遷移する。
- バッジは保存済み全明細の数量合計。0は非表示、100以上は「99+」。
- 認証・カート情報はCMN-01の共通管理を使用する。取得済み情報は共通仕様に従って再利用し、本画面への切り替えだけで重複取得しない。
- 認証確認・カート取得失敗時は、メニュー・数量を未確定として扱う。未ログインやカート0件と断定しない。
- ヘッダーの取得失敗でも本文と「商品一覧へ戻る」は表示し、操作可能とする。

### 2.2 未検出案内

| 要素 | 表示・動作 |
| --- | --- |
| 見出し | N01「ページが見つかりません」。 |
| 説明文 | N02。不存在・非公開・削除等で文言を出し分けない。 |
| 主導線 | 「商品一覧へ戻る」を常時表示する。SCU-01の検索条件なし・先頭からの初期表示へ遷移する。 |
| ブラウザのページタイトル | 「ページが見つかりません」。商品名など以前のタイトルを残さない。 |

- 不正なURLパス・パラメータ文字列を本文やページタイトルへそのまま表示しない。
- SCU-02からの切り替えでは、表示済みの商品名・画像・価格・説明・数量入力・カート追加等の商品領域を取り除き、本案内へ置き換える。
- 本文の表示は未検出が確定してから行う。商品データの取得中はSCU-02のローディング表示を使用する。

### 2.3 操作性

- 表示・共通表示への切り替え時に見出しへフォーカスを移す。
- 支援技術でも未検出状態を認識できるようにする。
- 主導線・ヘッダー・フッターのリンクはキーボードで操作できるようにする。

## 3. 適用条件・他画面との境界

| 条件 | 表示・制御 |
| --- | --- |
| ユーザー側の未定義ルート | ルーターの未検出判定後、本画面を表示する。 |
| SCU-02の商品ID未指定・形式不正 | 画面側で判定できる場合は商品APIを呼ばず共通表示へ切り替える。ID形式はAPI設計で定義する。 |
| SCU-02の商品不存在・非公開・削除済み | 商品取得または追加可否確認等のAPI応答から商品表示不可が確定した場合、共通表示へ切り替える。 |
| SCU-02の取得中 | ローディング。未検出表示にしない。 |
| 公開中の商品が売り切れ・販売停止 | SCU-02の商品詳細を維持し、売り切れ・現在購入できませんを表示する。本画面へ切り替えない。 |
| 通信失敗・サーバー障害 | 各画面の取得エラー・再読み込みを使用する。 |
| SCU-08の対象不明・参照不可 | SCU-08のP06・P07等を使用する。 |
| SCU-09の対象不明・参照不可 | SCU-09のD04を使用する。 |
| 保護画面への未ログインアクセス | 各画面の認証仕様に従ってSCU-03へ案内する。本画面を使用しない。 |
| 管理者側の未定義ルート | SCA-06で扱う。ユーザー側の未検出判定と分離する。 |

- 商品不存在等の判定は、API契約で定義された業務結果を使用する。HTTPステータスだけで商品不存在と判断しない。
- APIのURL誤り、配信設定の不備等の通信上のエラーを商品表示不可と混同しない。
- 不存在・非公開・削除済みの内部的な区別を利用者へ開示しない。

## 4. アクション・イベント

### 4.1 表示・切り替え

1. 未定義ルート、ID不正、または商品表示不可が確定したらN01・N02・主導線を表示する。
2. 本文表示のためにヘッダーの認証・カート取得完了を待たない。
3. CMN-01の共通管理に従って必要な情報を取得・再利用し、メニューとバッジを更新する。会員・ゲストの識別や依存関係は共通方式に従う。
4. 認証期限切れ・未ログインでも本画面からログインへ強制遷移しない。既に保持していた会員表示の破棄等は共通認証仕様に従う。
5. SCU-02の先行する古い応答で、未検出に切り替えた表示が商品詳細へ戻らないようにする。

### 4.2 商品一覧へ戻る

- SCU-01へ遷移し、検索条件なし・先頭からの商品取得を行う。
- ブラウザの戻る操作とは区別する。前の画面への復帰をこのボタンで代用しない。

### 4.3 URL・再読み込み・ブラウザ操作

- 未定義URLとSCU-02の表示不可では、アクセス中のURLを維持して共通表示する。未検出用URLへの転送は行わない。
- 共通表示への切り替えだけでブラウザ履歴を追加しない。戻る操作では元の履歴に従う。
- ブラウザの再読み込み時は同じURLのルート・対象データを改めて評価する。
- 商品再公開等により表示可能になった場合は通常のSCU-02を表示する。未検出状態を永久的に固定しない。
- 新しい再評価の応答と、それ以前の古い取得応答を区別する。
- ログアウト操作はCMN-01・共通ログアウト仕様に従う。

## 5. 状態・メッセージ一覧

| ID | 状態 | 文言 |
| --- | --- | --- |
| N01 | 未検出見出し | ページが見つかりません |
| N02 | 未検出説明 | お探しのページは移動または削除されたか、現在ご利用いただけません。「商品一覧へ戻る」から商品をお探しください。 |

- 主導線：「商品一覧へ戻る」。
- SCU-02で共通表示を使用する場合も同一文言とする。
- ヘッダーの認証確認・カート取得エラーの文言と再試行はCMN-01に従う。

## 6. 画面で必要なAPI連携項目

本画面固有の業務APIは設けない。本文は静的表示とし、ヘッダーは共通連携を利用する。URL・メソッド・物理名・型・結果コードはAPI設計で定義する。

### 6.1 認証状態確認（CMN-01共通）

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証・セッション情報 | 現在の利用者の認証確認。 |
| 受信 | 認証状態・処理結果・エラー種別 | ログイン／マイページ等のメニュー制御。認証未確定と未ログインを区別する。 |

### 6.2 カート合計数量取得（CMN-01共通）

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員認証情報、またはゲストカート識別情報 | 対象カート特定。 |
| 受信 | 保存済み全明細数量合計 | バッジ表示。 |
| 受信 | 処理結果・エラー種別 | 0件と取得失敗を区別する。 |

### 6.3 SCU-02から共通表示へ切り替える判定情報

| 情報 | 用途 |
| --- | --- |
| 画面側の商品ID検証結果 | 未指定・形式不正の場合のAPI呼び出し前の判定。 |
| SCU-02で受け取る商品の表示可否・業務結果 | 商品不存在等による表示不可と、売り切れ・販売停止・通信失敗を区別する。 |

- 6.3の情報はSCU-02の既存処理から利用する。本画面で商品APIを追加呼び出ししない。
- 画面上の未検出表示とHTTPレスポンスの扱いは、インフラ・機能設計で別途定義する。SPAフォールバックの対象範囲には、API・静的ファイル・管理者領域との境界を含める。
