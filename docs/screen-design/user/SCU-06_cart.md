# SCU-06: カート画面

## 1. 基本情報

- **物理名:** `cart`
- **対象:** 会員・非会員・ゲストユーザー。
- **目的:** カートの商品・金額・最新の販売状態を確認し、数量更新・削除・統合結果の確認と再試行を行い、注文手続きへ進む。
- **遷移先:** SCU-07（注文・決済確認）、SCU-03（ログイン）、SCU-02（商品詳細）、SCU-01（商品一覧）。
- **共通画面:** CMN-01（ユーザー側共通レイアウト）、CMN-02（ユーザー側共通フッター）。
- **対象外:** 複数配送先、クーポン・ポイント、お気に入りへの移動。
- **記載範囲:** 画面構成・入力・操作・表示状態・API連携項目。DB保存、有効期限、統合の内部処理、排他制御、在庫確保等は要件定義・機能設計で扱う。
- **文言:** 要件定義にも同じ文言を記載する。API設計時に結果コード・表示条件と照合する。文言IDは資料間の参照用であり、APIエラーコードではない。

## 2. 画面構成

### 2.1 共通レイアウト

- 上部にCMN-01、末尾にCMN-02、ページタイトルに「ショッピングカート」を表示する。
- 768px以上は明細を左、サマリーを右に配置し、768px未満は明細の下にサマリーを配置する。
- ヘッダーのバッジは購入不可分を含む保存済みの全明細数量合計を表示する。0は非表示、100以上は「99+」。未統合ゲストカートの数量を会員カートのバッジに独自加算しない。
- 取得・数量更新・削除・統合完了後は、APIの最新合計数量でバッジを同期する。未保存の入力数量を反映しない。
- 初回取得失敗は数量不明として扱い、0件と断定しない。

### 2.2 通知エリア

- タイトルの下に統合未完了、統合調整、購入不可、価格変動、再同期失敗等の通知を表示する。
- 統合調整時は、全体通知に加えて商品名・調整前後の数量・除外理由を表示する。除外商品も通常明細とは別に確認できること。
- 会員カートが空の場合も統合未完了の通知と再試行操作を残す。
- 統合が完了した場合のみ完了文言C12を使用する。

### 2.3 明細一覧

- 追加日時の昇順、同一日時は明細IDの昇順で表示する。数量更新では順序を変えない。

| 項目 | 表示・動作 |
| --- | --- |
| 商品ID | 商品詳細への遷移に使用する。非表示。 |
| カート明細ID | 数量更新・削除の対象指定に使用する。非表示。 |
| 商品画像 | APIのURLを使用し、代替テキストを設定する。未設定・取得失敗時はNo Imageへ切り替え、切り替えを繰り返さない。 |
| 商品名 | 現在の名称をテキストで表示する。取得不可なら追加時点の名称、いずれも不明なら「商品情報を取得できません」。APIが詳細遷移可とする場合のみSCU-02へのリンクとする。 |
| 税込単価 | 現在の税込単価を円単位・小数なし・3桁区切りで表示する。例：「￥1,980（税込）」。価格変更時はC13を併記する。 |
| 販売・在庫状態 | 「在庫あり」「在庫不足（残りN点）」「売り切れ」「現在購入できません」。色だけで区別しない。 |
| 保存済み数量 | APIで確定した数量を保持する。編集中は「保存済み：N点」を表示し、入力値と区別する。 |
| 数量入力 | 数値入力欄＋減算・加算ボタン。操作だけではAPIへ送信しない。 |
| 数量を更新 | 当該明細の入力値を保存する。保存済み数量と同一の場合は非活性とする。 |
| 入力を戻す | 編集中のみ表示し、当該明細の入力値を保存済み数量へ戻す。 |
| 明細小計 | APIが返す税込小計を表示する。商品合計への算入対象外なら「—」。単価×入力数量を画面で計算しない。 |
| 削除 | 販売不可の商品も削除できる。更新通信中・結果確認中は非活性とする。 |
| 明細別通知 | 入力エラー、在庫不足、更新失敗、価格変動を当該明細付近に表示する。 |

- 商品名等に含まれるHTMLは実行しない。
- 金額が欠損・不正な場合は「取得できません」と表示し、0円に補完しない。算入判定・数量・在庫・販売情報が不明な場合は注文へ進めない。

### 2.4 サマリー・導線

| 項目 | 表示・動作 |
| --- | --- |
| 商品合計（N点） | 購入可能かつ保存数量が在庫内の明細の数量合計。APIの値を表示する。 |
| 税込商品合計 | 上記対象明細の税込商品合計。例：「￥5,940（税込）」。画面で再計算しない。 |
| 対象外の案内 | 算入対象外の明細があればC22を表示する。在庫不足明細は在庫分だけを部分算入せず、明細全体を対象外とする。 |
| 送料等の案内 | 「送料・手数料は注文確認画面でご確認ください。」を表示する。商品合計を最終請求額として表示しない。 |
| 未保存の案内 | 編集中はC19を表示し、金額と点数は保存済み数量に基づくことを明記する。 |
| レジへ進む | 有効な保存済みカートで、未反映入力・統合未完了・処理中・結果不明等がない場合のみ活性。 |
| お買い物を続ける | SCU-01へ遷移する。空カート・取得失敗時も利用可能。 |

- 空カートではC01を表示し、サマリーと「レジへ進む」は非表示にする。
- 1件以上あるが全明細が算入対象外の場合は、取得できたAPIの合計値とC22を表示し、注文操作は非活性にする。

### 2.5 操作性

- リンク・数量入力・増減・更新・削除・再試行をキーボードで操作できるようにする。
- ボタン名は対象商品を識別できるものとする。例：「〇〇の数量を減らす」。
- 明細削除後・空カートへの切り替え後もフォーカスの移動先を確保する。
- 更新・完了・エラーを支援技術でも認識できるようにする。

## 3. 入力・操作制御

### 3.1 数量入力

- 1以上の整数とし、保存可能な上限は表示中の在庫数とする。商品別の購入上限は設けない。
- 空欄・0・負数・小数・数値以外はC03、表示在庫超過はC04を表示し、APIを呼び出さない。0による削除は行わない。
- 減算は1で非活性、加算は在庫数以上で非活性とする。
- 保存数量が在庫超過の場合も減算を可能とし、在庫数以下まで入力を減らせるようにする。中間の在庫超過値は保存せず、任意の有効値へ直接入力することも可能とする。
- 数値として不正な入力中は増減を非活性にし、入力欄での修正・「入力を戻す」を受け付ける。
- 不正な入力を自動で切り捨て・在庫数へ丸めて送信しない。
- 未保存値・入力エラーが1件でもあればC19を表示し、「レジへ進む」を非活性にする。

### 3.2 明細とカートの状態

| 状態 | 数量操作 | 削除 | 注文へ進む |
| --- | --- | --- | --- |
| 販売可能・保存数量が在庫内 | 可 | 可 | 他の阻害条件がなければ可 |
| 販売可能・保存数量が在庫超過（在庫1以上） | 数量修正可 | 可 | 不可 |
| 在庫0 | 非活性 | 可 | 不可 |
| 販売不可・状態欠損 | 非活性 | 可 | 不可 |
| 統合未完了だが未処理・失敗確定で状態が確認済み | 会員カートの更新可 | 可 | 不可 |
| 数量更新・削除・統合・注文前検証の通信中 | カート全体で非活性 | 非活性 | 不可 |
| 更新・削除・統合の結果不明／最新状態の確認失敗 | 非活性 | 非活性 | 不可 |

- 購入不可・在庫不足が1件でもあればC05を表示する。算入対象外を自動で除いて注文へ進めない。
- 統合結果不明は通常の統合失敗と区別し、結果を確認するまで更新・再統合を行わない。
- 価格変更の通知だけで永続的に注文操作を止めない。注文前検証で新たな価格変更が判明した場合は4.5に従って再確認する。

## 4. アクション・イベント

### 4.1 初期表示・カート再取得

1. 認証状態を確認し、利用者に対応するカートを取得する。取得中はローディング表示を出す。
2. 認証確認の通信失敗はC14と再読み込みを表示する。未ログインと断定しない。
3. ゲストと確認できた場合はゲストカートを取得する。会員カート利用中の認証無効は会員表示を破棄し、戻り先SCU-06でSCU-03へ案内する。ゲストの空カートへ黙って切り替えない。
4. 成功時は保存済みの明細・金額・数量・状態・統合情報を反映する。0件ならC01とバッジ非表示。統合通知は空状態でも保持する。
5. 初回カート取得失敗はC02と再読み込みを表示する。既存表示がある再同期失敗はC18を表示し、古い表示を最新と扱わず更新・注文操作を止める。

### 4.2 数量を更新

1. 入力を検証し、変更がなければ送信しない。更新対象の明細IDと変更後の絶対数量を送る。
2. カート全体の更新操作と注文操作を非活性にし、対象明細に「更新中…」と表示する。
3. 成功時は最新カートを反映し、対象明細の入力値と保存済み数量を一致させる。小計・合計・バッジ・販売状態・注文可否を同期する。
4. 失敗確定時は在庫不足C06、販売不可C07、その他C09を表示する。最新の保存済み数量を応答または再取得で確認し、対象入力をその数量へ戻す。確認できない間はC18とする。
5. 結果不明時はC15を表示し、自動再送せず、カートと必要な処理結果を照会する。単なる取得成功だけで未完了処理が確定したとみなさない。
6. 結果と現在状態の同期が確認できた後に操作を再開する。確認できなければC18と再読み込みを表示する。

### 4.3 削除

1. 確認ダイアログを挟まず、対象明細IDで削除する。カート全体の更新・注文を非活性にし「削除中…」と表示する。
2. 成功時は対象明細とその編集中入力を除去し、最新カート・バッジを同期してC08を通知する。0件なら空表示へ切り替える。
3. 対象が既に存在しない場合も最新カートへ同期する。
4. 失敗確定時はC10を表示する。結果不明はC16とし、自動再送せず結果確認・カート再取得を行う。
5. 結果と最新状態が確認できるまで更新・注文を再開しない。確認失敗はC18とする。

### 4.4 統合結果・再試行

1. 統合未完了で再試行可能ならC11と「カート統合を再試行」を表示する。会員カートの閲覧・更新・削除は可能とするが、注文へは進めない。
2. 未保存の数量入力がある場合は、更新または「入力を戻す」で解消するまで統合再試行を非活性にする。
3. 再試行中はカート全体の更新・注文・再試行を非活性にし「統合処理中…」と表示する。
4. 統合完了時は最新カートとバッジを同期し、C11を解除する。調整・除外があればC12と具体的な変更内容を表示する。
5. 失敗確定時はログインを維持してC11を残す。最新状態が確認できたら会員カートの更新と再試行を再開可能にする。
6. 結果不明はC17を表示し、結果確認後に安全な再試行へ案内する。確認失敗はC18とし、未確認のまま統合を再実行しない。
7. 認証期限切れの場合はSCU-06を戻り先としてSCU-03へ案内し、未統合状態を失わない。統合元・結果確認の管理方式は共通設計で定義する。

### 4.5 レジへ進む

1. 保存済み明細が1件以上あり、すべて購入可能・在庫内であることを確認する。未保存入力、統合未完了、通信中、結果不明、必要情報欠損があれば操作不可とする。
2. ゲストの場合はC23を案内し、戻り先SCU-06としてSCU-03へ遷移する。ログイン・統合後はSCU-06で内容を確認して、改めて操作する。
3. 会員の場合は注文前検証を実行し、「確認中…」を表示して更新・注文の重複操作を防ぐ。
4. 検証で在庫不足・販売不可が判明したら最新カートを反映し、C05と明細エラーを表示する。空になった場合は空表示にする。
5. 利用者が直前に確認した価格から変更が判明した場合は、最新価格・商品合計とC20を表示し、その回は遷移しない。再度「レジへ進む」を押したときも最新検証を行い、さらに価格が変わっていなければ進行できる。
6. C13の「追加時からの変更」と、C20の「今回の検証で新たに判明した変更」を区別する。C13が残っているだけで再確認を無限に要求しない。
7. 他端末の操作等で数量・明細構成が画面から変わっていた場合もC24で再確認を促し、その回は遷移しない。
8. 検証成功かつ新たな変更がなければSCU-07へ遷移する。検証失敗はC21と再試行操作を表示し、成功とみなして遷移しない。
9. この検証で価格・在庫を確保した旨は表示しない。SCU-07および注文確定時の再検証は各機能設計に従う。

### 4.6 別タブ・戻る操作・競合

- SCU-07・SCU-02からの復帰、別タブからのフォーカス復帰時は認証・カートを再確認する。
- 数量編集中または更新通信中は背景の再取得を保留し、編集が保存・取消で解消され処理が確定してから再同期する。保留中はC25を表示する。
- 別明細に未保存入力がある状態で更新応答を受けた場合も、その入力を黙って破棄しない。保存済み値は最新化し、入力は未保存として保持して再検証する。対象が削除・販売不可になった場合は入力を破棄して変更を通知する。
- 競合が検出された場合は自動で上書きせず、最新カートへ同期してC24で確認を促す。保持できない編集を破棄した場合も通知する。
- 結果確認中・保留中の応答、画面離脱前・会員切替前の古い応答で現在の表示を上書きしない。
- ログアウト・会員切替時は会員カートの表示・編集値・復元用データを破棄し、共通認証仕様に従う。

## 6. 画面で必要なAPI連携項目

以下は論理項目。URL・メソッド・物理名・型・結果コードはAPI設計で確定する。更新後にカート全体を返すか追加取得するかは、画面全体の整合した表示を満たす方式を選ぶ。

### 6.1 認証状態・カート詳細取得

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証情報、またはゲストカート識別情報 | 対象利用者・カートを特定する。 |
| 受信 | 認証状態・処理結果・エラー種別 | 会員／ゲスト／認証無効／通信失敗を区別する。 |
| 受信 | カート識別・版情報等（方式は後続設計） | 対象の取り違え、更新競合、古い応答の反映を防ぐ。 |
| 受信 | 明細配列 | 追加日時昇順・同一日時は明細ID昇順で表示する。 |
| 受信・明細ごと | 商品ID・明細ID | 商品詳細遷移、更新・削除の対象指定。 |
| 受信・明細ごと | 現在の商品名・追加時点の名称（必要時） | 現在名とフォールバック表示。 |
| 受信・明細ごと | 画像URL・詳細遷移可否 | 画像・リンク制御。 |
| 受信・明細ごと | 現在の税込単価・追加時からの価格変更有無 | 単価・C13表示。 |
| 受信・明細ごと | 保存済み数量・税込小計 | 数量・小計表示。 |
| 受信・明細ごと | 最新在庫数・販売可否・不可理由 | 状態と操作の制御。購入上限数は設けない。 |
| 受信・明細ごと | 商品合計への算入可否 | 対象外の小計「—」、全体案内の表示。 |
| 受信 | 全明細の保存済み数量合計 | ヘッダーバッジ。 |
| 受信 | 購入対象の数量合計・税込商品合計 | サマリー。 |
| 受信 | 注文手続き進行可否・阻害理由 | ボタンと警告の制御。認証・入力・処理中の画面条件と合わせて判定する。 |
| 受信 | 統合状態・再試行可否・調整情報 | 未完了・処理中・完了・結果不明、通知と再試行を制御する。 |

### 6.2 数量更新・削除

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 共通認証情報／ゲストカート識別情報 | 対象カートの特定。 |
| 送信 | 明細ID | 対象明細指定。 |
| 送信・数量更新のみ | 変更後の数量 | 加算差分ではなく絶対数量。 |
| 送信・必要時 | 更新元の版・操作識別情報 | 競合検出・結果照会・安全な再試行。方式は機能設計で確定。 |
| 受信 | 処理結果・エラー種別・処理確定状態 | 成功・失敗・処理中等、在庫不足・販売不可・対象なし・競合を区別する。 |
| 受信 | 最新カート情報（6.1相当）・操作結果の識別情報 | 明細・金額・数量・バッジ・注文可否を整合させ、必要時に結果確認する。 |

### 6.3 カート統合の再試行・結果確認

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員認証・未完了の統合手続きの識別情報 | 統合先・元・処理を安全に特定する。ゲストカートの識別と所有権確認は共通方式に従う。 |
| 受信 | 処理結果・統合状態・再試行可否 | 完了・未完了・処理中・結果不明の表示と操作制御。 |
| 受信・調整ごと | 商品識別情報・通知用商品名・調整前後の数量・除外理由 | 除外された明細も含めて変更内容を表示する。 |
| 受信 | 統合後の最新カート情報 | 全体とバッジの同期。 |

### 6.4 注文前検証

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 会員の認証情報 | 注文に進む会員の特定。 |
| 送信・必要時 | 利用者が確認したカート版・価格情報の識別子 | 表示時からの価格・数量・明細変更を検出する。具体的方式はAPI設計で確定。 |
| 受信 | 検証結果・進行可否・阻害理由 | SCU-07への遷移または警告表示。 |
| 受信 | 最新カート情報・確認時点からの変更有無と対象 | 最新表示と価格・内容の再確認。追加時からの価格変更とは区別する。 |
| 受信・必要時 | 検証済み状態の識別情報 | SCU-07への引き継ぎ。価格・在庫の確保を意味しない。 |

### 6.5 更新結果の照会・再同期

| 方向 | 項目 | 用途 |
| --- | --- | --- |
| 送信・付随 | 利用者・カートの識別情報、対象操作の識別情報（必要時） | 結果不明となった数量更新・削除等を照会する。 |
| 受信 | 処理中／成功／失敗／未確認の区別、最新カート情報 | 結果が確定して同期できたかを判定し、操作を再開する。 |

- 6.3・6.5の独立API新設は必須としない。カート再取得だけでは更新処理の完了を証明できない場合の確認方法を、機能設計・API設計で定義する。
