# CMN-02: ユーザー側共通フッター

## 1. 基本情報

- **物理名:** `user-common-footer`
- **対象:** 会員・非会員・ゲストユーザー。
- **適用画面:** SCU-01〜SCU-10。
- **目的:** コピーライト、模擬ECサイトの注意表記、商品一覧と管理者ログインへの導線を提供する。
- **遷移先:** SCU-01（商品一覧）、SCA-01（管理者ログイン）。
- **連携:** CMN-01と各画面の処理状態・通常の遷移許可状態を共有する。
- **対象外:** 管理者側フッター（CMN-04）、メルマガ登録、外部SNS連携、実在企業の運営・法務ページへの遷移、規約等の個別画面。
- **記載範囲:** 配置、表示、操作、遷移抑止、文言、共通連携項目。認証・権限の内部処理は管理者側・共通機能設計で定義する。
- **文言:** 要件定義にも同一文言を記載する。文言IDは資料間の参照用であり、APIコードではない。

## 2. 画面構成

### 2.1 配置

- メインコンテンツの後に通常配置する。固定・スクロール追従は行わない。
- ページ全体の最小高さを表示領域の高さに合わせ、内容が少ない場合はメイン領域で余白を確保してフッターを下部に配置する。本文に重ねない。
- 内容が長い場合はその末尾に配置し、ページ全体をスクロールして到達できるようにする。
- SCU-01では「もっと見る」や一覧下部メッセージの後に置く。追加取得を実行しなくてもフッターへ到達できること。
- 768px以上はリンク・注意表記・コピーライトを行単位に整理し、768px未満は左右余白を確保して縦方向に配置する。

### 2.2 表示要素

| 要素 | 表示・動作 |
| --- | --- |
| トップページ（商品一覧） | SCU-01の検索条件なし・先頭からの初期表示へ遷移する。 |
| 利用規約（デモ・未実装） | 非リンクのテキスト。遷移・クリック操作は設けない。 |
| プライバシーポリシー（デモ・未実装） | 非リンクのテキスト。遷移・クリック操作は設けない。 |
| 特定商取引法に基づく表記（デモ・未実装） | 非リンクのテキスト。遷移・クリック操作は設けない。 |
| 管理者ログイン | 常にSCA-01へ遷移する。管理者ログイン済みの場合のSCA-02への遷移はSCA-01側で判断する。 |
| デモ注意表記 | UF02を常時表示する。 |
| コピーライト | UF01を表示する。年は2026の固定表記とし、自動更新しない。 |

- 規約等はリンクと区別できる外観にする。不要なTabフォーカス、リンク用カーソル、リンクとしての意味付けを付けない。
- `href="#"`、未実装ページへのリンク、クリックしてSCU-10へ移動するダミーリンクは設けない。

### 2.3 操作性

- 有効なリンクはTab・Enterで操作でき、フォーカス位置が分かるようにする。
- フッターをページ末尾の領域として支援技術が認識できるようにする。
- 遷移抑止中は見た目に加え、クリック・キーボード操作によるアプリ内遷移も抑止する。非活性状態を支援技術へ伝える。
- 文字の折り返しによって、狭い画面でも横方向のはみ出しを防ぐ。

## 3. 表示・操作制御

### 3.1 認証・取得状態

- 認証確認中・ログイン済み・未ログイン・認証確認失敗・カート取得失敗・本文の取得失敗のいずれでもフッターを表示する。
- 本文や共通ヘッダーの通常の読み取り通信だけを理由にリンクを停止しない。
- 本フッターのための管理者認証確認APIは呼び出さない。管理者認証・権限判定はSCA-01以降で行う。
- 管理者リンクを表示していても、ユーザーのログイン状態を管理者権限の根拠として扱わない。

### 3.2 遷移抑止

| 共通状態 | フッターの動作 |
| --- | --- |
| 通常の遷移を許可 | 商品一覧・管理者ログインのリンクを操作可能にする。 |
| ログイン、登録・メール確認、カート更新・削除・統合、注文確定、ログアウト等の重要処理通信中で通常遷移を禁止 | 両リンクを一時的に非活性にする。文言・コピーライト等は表示を続ける。 |
| 処理結果不明で、復旧操作のみ許可 | 両リンクの抑止を継続する。画面本体の結果確認等は各画面仕様に従う。 |
| 結果不明でも各画面が通常の離脱を許可 | 共通の許可状態に従ってリンクを操作可能にする。離脱後の結果照会・再開は各機能で維持する。 |
| 通常の読み取り通信中 | 他の遷移禁止条件がなければリンクを操作可能にする。 |

- 「復旧ボタンが使える」ことだけを根拠に、フッターの全リンクを自動で有効化しない。
- CMN-01・画面本体・CMN-02は同じ遷移許可状態に従う。フッター独自のタイマーやAPI応答だけで解除しない。
- ブラウザの戻る・再読み込み・タブ終了を確実に防ぐ仕組みとして扱わない。

## 4. アクション・イベント

### 4.1 トップページ（商品一覧）

1. 共通の通常遷移許可状態を確認する。禁止中は遷移しない。
2. SCU-01の初期表示へ遷移する。
3. 既にSCU-01を表示中の場合も、検索条件をクリアし、先頭から取得する。

### 4.2 管理者ログイン

1. 通常遷移が許可されている場合のみ実行する。
2. SCA-01へ同じタブで遷移する。
3. 管理者のログイン状態・権限と遷移先はSCA-01側の仕様に従う。
4. このリンク操作自体によってユーザーのログアウト、会員・ゲストカートの削除、認証情報の管理者への転用を行わない。

### 4.3 画面遷移・状態更新

- 遷移先のフッターも同じ構成で表示する。
- 共通の遷移許可状態が変わったら両リンクへ反映する。以前の画面の抑止状態を不用意に残さないよう、共通レイアウト側で管理する。
- フッター固有のローディング・エラー通知・再試行処理は設けない。

## 6. 画面で必要なAPI連携項目

- 本コンポーネント固有のAPI通信はない。
- 表示のための認証・カート・管理者権限照会も本コンポーネントからは行わない。

### 6.1 共通状態の連携（API通信なし）

| 情報 | 用途 |
| --- | --- |
| 通常の画面遷移を許可するか | 両リンクの活性・抑止を決定する。画面本体とCMN-01で共有する。 |
| 重要処理中・結果不明・許可する復旧操作の範囲 | 共通管理側が通常遷移の許可を判断する。結果不明と通信中、復旧操作と通常離脱を区別する。 |
| 現在の画面・遷移先 | SCU-01での検索解除、SCA-01への遷移、画面切替時の状態管理。 |
